# 派活任务书与并行工作的契约

给 ZCode 一类外部 agent 写 `dispatch-*.md` 时照下面的骨架与条款；每一条都来自验收时真拦住过的问题，不是格式偏好。

## 一、任务书骨架（顺序固定）

1. **铁律**：纯追加的边界、不猜值的处置、批末只许三件事、额度/限流停手条件。
2. **材料在哪**：页图两套（高清 + 入库标准）、OCR 源、代码与测试文件、读数方法论、工具绝对路径。
3. **目标表**：逐项列「图/表号 + 印刷页 + 页图 + 目标内容」，一行一项，验收时按行勾。
4. **交付形状**：函数签名、数据 dict 的 schema（照抄同文件里已验收那几条的形状，别自创）、越界行为。
5. **测试**：锚点值 + 出处（例题/OCR 行/页图），以及**没有外部锚点时怎么办**（见第五节）。
6. **分工波次**：按**版面工作量**切，不按目标个数对半；写清每段只做自己那段。
7. **不许碰**：另一路并行工作的文件、进度表、git 操作。
8. **批末**：写回执 + `PAUSED-批N.md`，明写「待验收」。
9. **预算与模型**：预估、硬停线、工期、并发，以及开工第一回合要回哪几行。

## 二、纯追加任务：把「唯一允许的删改点」写死

「只许追加、不许改任何一行」这类条款，遇到「启用数据」就自相矛盾——把某项从未支持变支持，必须**从「未支持清单」里删掉对应键**。写法：

> 唯一允许的删改：常量 `_未数字化材料`（或等价清单）里删掉本次已数字化的键；别处一行都不许少。

验收命令同时给出来，判据是「删行全部落在那几个常量里」：

```bash
git -C <repo> diff -U0 <改动文件> | grep '^-[^-]'   # 逐行看每一处删改
```

没有这条豁免，执行方要么不敢动清单（功能永远启用不了），要么顺手改了别处还自认为在「补全」。

## 三、子代理 handoff：字段固定，缺一退回

每段交一份 JSON，主代理**用脚本读 JSON 生成代码**，不许手抄数字：

```json
{"段": "S1", "目标": "图10-20(a)", "印刷页": 219, "页图": "ch10/p022.png",
 "裁图区域": [x0,y0,x1,y1],
 "横轴": {"量": "HBW", "范围": [100,350], "像素标定": {"x0":0,"x1":0,"值0":0,"值1":0,"残差_px":0}},
 "纵轴": {"量": "MPa", "像素标定": {}},
 "曲线": [{"名": "MQ", "图例行": "3", "点集": [[0,0]]}],
 "疑点": [{"位置": "…", "现象": "…", "差多少": "…"}],
 "复现命令": ["…"],
 "confidence": "verified | partial"}
```

`confidence != verified` 的项在库里保持 `NotImplementedError`，别降级落库。

## 四、并行：自己改套件 vs 外部跑批

两路同时开工时按「文件级隔离 + 定向测试 + 提交分开」三条走，别靠自觉：

- **文件级隔离**：在任务书第 7 节列出「这一路只许写哪些文件」，并把自己即将改的目录也列进去；两边文件集不交叠，才谈得上并行。
- **跑批期间只跑自己模块的单测**，不跑 `mdkit.py test all` 一类全量：全量会把对方未完成的改动一起算进失败，你会误判成自己改坏了。等交批 → 验收（这时才跑全量）→ 合并 → 再跑一次全量。
- **提交只由主控做**，任务书里明写「不许 `git add/commit/push`」。这样 `git diff` 永远是「对方改了什么」的纯净证据，也避免它 `git add -A` 吞掉你的在写改动。
- 共享契约文件（`_lookup.py`、图元库 `gbdraw` 之类）谁都不许动；要新能力就在新模块里组装现成图元。

## 五、没有外部锚点时的断言怎么写

教材例题只覆盖其中一部分材料/工况时，其余条目**没有书值可对**。这时断言分三类，缺一不可，而且必须在回执里如实声明性质：

1. **图内锚点自锁**：在刻度交点处读数、容差 ±2%（图读误差）。它锁的是「这次读出来的数不被静默改动」，**不是**与书值互证——回执要这么写，别把自锁说成交叉验证。
2. **结构关系**：曲线族排序（如 ME ≥ MQ ≥ ML）、随横轴单调不减（允许平台相等）。
3. **负向**：超范围抛 `ValueError`、不存在的组合抛 `ValueError`、已数字化的键仍在字典里、未支持清单里不再出现本次已做的键。

## 六、把前批的先验写进任务书

上一批留下的「判过做不成」的结论必须原样传下去，否则新一批会重推一遍、或为了「做完」随手指定一个归属：

- 写明**为什么没做成**（线交叉/虚线断续/无锚点可标定），以及本次允许仍然不做成的条件；
- 要求升级证据（已排除的组合、每条线的点集、交叉点位置），而不是要求「必须交数」；
- 前批留过实测参考值的，把参考点写进任务书并规定「新读数与参考差 >5% 先怀疑自己的标定」。

## 七、页图像素坐标不跨渲染换算

不同来源的页图（高清放大版 vs 入库标准版）**裁切范围常常不同，坐标不能按比例线性换算**——标准图上的图题 y 直接拿去裁高清图，会裁到网格或图例上。任务书里的做法：

- 只给「印刷页 → 页图」的对应关系，**不给像素坐标**；
- 让执行方自己对要用的那张图跑一次 OCR 取图题坐标，再往上裁分图区域；
- 裁完先出一张缩略图用视觉确认「这是数据区（有网格、有材料名/曲线）」，再开始读数。

## 任务书规矩：一份、无元话、不重复

> 自 `SKILL.md` 下沉（2026-10-26 文档整理，正文未改）。

- **一份可粘贴的文件，别用 `cat` 拼接多份**。拼接会把「用法：先贴这段，再贴调度任务书」这类**写给人看的操作说明**带进正文——主代理会把那行当成自己的指令，用户也会当场问「为什么有这段话」。怎么使用是对话里说的话，不进交付文档。
- **同一件事只写一次**：现状、已知坑、纪律在一份里出现一遍即可。合并后**删掉源文件**，不要「合并版 + 原三份」并存——用户会直接说「文档太多了，不要留重复内容」。
- 交付目录只留四类：①唯一可粘贴任务书 ②人读地图 md（勘误在末节）③机器读 `章节地图.json` ④原始扫描缓存 `页眉扫描.jsonl`，外加临时产物目录 `_split/`（渲完页图就删）。第五个 md 起就是冗余。
- 验收标准写进任务书本身（双解释器退出码、表值逐格、例题反算），并明写「子代理自称核过不算证据」——否则回执会变成漂亮的自述。
- **状态词只许写「待验收」；「已验收」是用户专用词，Hermes 也不抢先填**：Hermes 出的是验收记录（本项目已合并成 `books/<书>/验收记录.md`，按批一节）与三关结论（说「我这边三关过了」），进度表那一列等用户一句确认再改成「已验收（抽查过）」。外部 agent 会把「自检通过」写成「✅ 已验收」，然后顺势跑下一批（批 2、批 3 连跑，未验的章被标成通过，验收顺序作废）。任务书里显式写「每批结束必须停止并等待明确回复『继续』」；进度表里看到「已验收」而行号还是它自己填的，一律当「待验收」处理并回问。
- **验收—续跑是一对，不能只做一半**：发「继续」给 ZCode 的同一步里，必须立刻用 `--min-batch N+1` 重启监视器（`scripts/watch_batch_run.py --min-batch N+1`，`persist_on_release=true`）。只发「继续」不重启监视，就等于把后续批次全交给对手的自觉——用户会当场发现「你怎么不继续监控了」。监视器要能抗 ZCode 轮转 `rollout/model-io-<task_id>.jsonl`（会消失），判活靠 artifacts/agents/sqlite/产物树多处 mtime；已验收批次的 `PAUSED-批N.md` 会残留，必须 `--min-batch` 排除，否则一启动就误触发。
- **「停」要机械化，不能只写一句「请停下」**：ZCode 会把「自检跑绿」当成「可以继续」。任务书顶部放一条**铁律第一条**，规定批末只许做三件事——更新进度表写「待验收（自检已过）」、写 `PAUSED-批N.md`、交回执——然后**结束本轮不再调用工具**，并预先写明「就算下一章只差一张表也停下」。已违规就要求把越界章改回「未开始」并在回执里报章号。用户为此专门提醒过两次（「不然有可能又像之前那样刹不住车」），两本任务书都按此写。
- **子代理分工要写死进任务书**（用户两次提醒过这条）：只说「五类工作」不够，必须给出角色表（每章 6 个：表值前半 / 表值后半 / 判据 / 标注复现 / 勘误 / 建库）、每个角色的 handoff 文件名、开工前三条（报材料缺口、**声明是否有视觉能力**、复述硬约束）、以及「章内 B 没核完 C 不开工 / 章内自检没绿不开下一章」的串行闸。不给角色表，ZCode 就用一个主代理从头串到尾——那是几小时的串行读图，正是用户要避免的。
- **handoff JSON 字段固定**，表值/判据/标注/勘误四类各有 schema（见 `references/sedimentation-delegation.md` 的「handoff JSON（字段固定）」一节与 `references/dispatch-contracts.md` 第三节）；`confidence != verified` 只许写 `raise`，不许写成可查值的函数。
- **任务书里的结构自检别写死注册表属性名**：各批章库不是同一版写法——新的有 `表字典清单` / `_表变量`，早的（如 ch10 那批）两者都没有；`png` 键也是后加的（老章库只有 `页`）。回归断言一律「扫 `vars(module)` 里含 `表号` 的 dict 再数」，写成 `len(模块.表字典清单) == N` 会让执行方在自检那步撞 `AttributeError`，得自己绕过去再在回执里解释一遍。同理，跨章脚本不要假设字典键集完整（取 `页` 前先 `d.get`，别直接 `d["png"]`）。
- **改批次计划要同改三处，否则「欠账」是文档造出来的**：用户改计划（换章、收手、暂缓）时，① 任务书第 8 节的批次表、② `沉淀进度.md` 的「批次」栏、③ `_批队列.md` 三处必须一起改。只改 `_批队列.md` 的后果实测过：任务书与进度表仍写着「批2 = ch07/ch12/ch17/ch18」，实跑只做了 ch17/ch18（ch20 是改计划时换进来的），用户按旧定义对账，当场认定「批2 才做了一半」——产物没错、记录也没错，是两套定义并存。批号改完 `grep -rn 批2` 扫一遍，确认没有第二份定义还在。
- **计划变更把某章挪出原批时，要把差额写死**：回执与批队列里明写「本批名义 N 章、实跑 M 章，差的章挪到批Xb」，别让缺口悬空——悬空的缺口下次会以「是不是漏了」的形式重新问一遍。实例：手册原定批4 = ch02/ch08/ch14/ch15，实交只有 ch14+ch19，差额没写死，收官时才被翻出 ch15（0 表 2 式）整章没做。

## 派活前的材料核对（图号 / 页范围 / 分图定位）

> 自 `SKILL.md` 下沉（2026-10-26，正文未改）。

**任务书与验收记录里的图号必须 grep 原文确认。** 凭印象把「图8-51 两齿轮啮合画法」写进靶子，实际图8-51 是「齿轮啮合时名称」，真正的画法是图8-54/8-55——这类错会让执行方做错图白干一轮。规矩：写图号前 `grep -n "图N-NN" raw/sources/<book>/chNN-全章OCR.md` 看它自己的图题，页码用 `## p.` 标记或页眉现算。表格页码同理：抽表时用页图直接核实「整表是否在本页、有无续表」，不要信任务书里手写的页码范围。

**用户给的页范围也要先验内容，再派活。** 图例/参考图章（ch20 那种一页一图）先按 `## p.NNN（章内第 k 页）` 把全章 OCR 切开，逐页 grep 图题，把「这个范围里实际是什么图」列出来给他确认。实测：用户说「ch20 只做 p276–284，给以后画零件图参考」，而那 9 页全是**减速器结构图**（图20-13/14/16/17/18/19），真正的零件工作图在 p268–272（图20-5 齿轮 / 20-6 轴 / 20-7 齿轮轴 / 20-8 箱盖 / 20-9 箱座）。照原范围跑一轮等于白干。
处理方式：先摆内容（每页图号 + 类型），再一次问清——A 按真实目标换范围、B 严格按他说的、C 两段都做（默认推 A）。**既不要默默照做，也不要默默改成自己想的范围。**

**分图（a/b/c…）到底在哪一页，用 ocrbox 抓图题坐标，不靠目录和印象。** `bin/ocrbox pNNN.png | grep -E '（[a-e]）'` 会把「（a）铸铁的 σ_Flim」这类图题连同 `x y w h` 一起吐出来，按 y 排序就能定每张分图落在哪页、页面哪一块（图题在图下方，图体在 y 更小的区域）。派活前把「段 / 图号 / 分图 / 印刷页 / 页图 / 图题 y」列成表写进任务书，执行方直接按坐标裁图，省掉它自己翻页找图，也避免把邻页或邻分图的曲线当成目标。
同章还有两件常忽略的：整页图页在 OCR 里没有分节（`## p.` 段会跳号），这些页必须回 `pNNN.png` 核；参考图例的数据落**表型书**（`lib/<book>/refdraw_chNN.py`：图号/页/页图路径 + 逐条标注条目 + 对应表号），不要往图样书里再存一份——图上每个值都要用表值与 `_anno.py` 反算，两份数据必然漂移。
