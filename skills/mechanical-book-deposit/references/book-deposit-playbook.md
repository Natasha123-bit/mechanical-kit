# 整本教材沉淀 · 可复用方案（v2，濮良贵一书实战定型）

> 用法：换一本书时只改 4 个参数——`<书PDF>`、`<书目录json>`、`<工作目录>`、`<知识库目录>`；其余流程照抄。
> 角色分工：**Hermes 只出方案、任务书、验收**；批量执行（OCR、按章写库、跑自检）交给 ZCode 子代理。

---

## 阶段 0 · 先判定这本书要不要 OCR（10 分钟，必须做）

```bash
pdftotext -f 50 -l 52 <书PDF> - | head -40     # 看抽出来的中文是否可读
```

- **文本层可读** → 直接 `pdftotext` 分章抽文，跳过整条 OCR 链（省 90% 时间）。
- **乱码/空白（扫描版）** → 走阶段 1 的 Swift+Vision 链。

输出：在 `<工作目录>/` 建 `raw/sources`（全书/分章文本）、`raw/assets`（页图）、`handoff-chNN`（每章中间产物）。

## 阶段 1 · 章节地图与分章拆分（机器做，不请模型）

```bash
cd <技能>/scripts
swiftc -O chmap.swift -o chmap          # 页眉识别「第N章」+ 印刷页码
./chmap <书PDF> > chmap.jsonl
```

1. 手抄一遍目录 → `book_toc.json`（章名 + 起始印刷页，只信目录当**候选**）。
2. `mdkit.py prepare --book <书PDF> --chmap chmap.jsonl --report-only` 对账；**边界以页眉实测为准，目录只在页眉读不出时才用**，差异写进勘误段（`book_prepare.py` 的 ERRATA）。
3. 逐章出料：`--only 8,9`（单章 PDF + 页图 + OCR 源 `chNN-全章OCR.md`）。一页 3~5 s，406 页约 25 min。

**坑**：印刷页与书内 PDF 页的偏移在书中不恒定（本书前段 4、后段 3），必须逐章标定；章末常多切 1~3 页（篇首页/下章开篇），要在勘误里写明，别去改 raw。

### 阶段 1·变体：手册类（没有「第N章」页眉）

`chmap` 会全输出 null（实测《机械设计课程设计手册》第5版 330 页无一命中）。换这条链，细节见 `book-splitting.md` 第 7 节：

```bash
bin/ocrpdf <整本.pdf> 1 <总页> _full_ocr          # 整本逐页 OCR 一次，约 0.6 s/页
python3 books/<book>/parse_footer_pages.py _full_ocr > 页脚扫描.jsonl   # 页脚页码 → 伪 chmap
mdkit.py prepare … --chmap 页脚扫描.jsonl --toc books/<book>/book_toc.json --report-only
mdkit.py prepare … --no-ocr                      # 只拆章 PDF + 渲页图
python3 book/assemble_sources.py 章节地图.json _full_ocr <sources>/<book> --slug <book> --chmap 页脚扫描.jsonl
```

必须做的两件事：① 锚点过滤改成「偏移众数 ±2」（写死 `2..5` 会让锚点全丢，地图直接空），改完拿老书 `--report-only` diff 到一字不差；② 逐章核对章首页 OCR 首行是不是「第N章 章名」，目录页码会错（本书第15章目录 207、实际 208）。

## 阶段 2 · 出任务书（Hermes 的工作）

给 ZCode 的提示词必须含 6 件事，缺一条就会跑歪：

1. **每章产物形态**：`xxx_chNN.py`（编号式函数 + 表字典）+ `xxx_chNN_tests.py`（断言）；概念章写 `references/chNN-general-notes.md`，不许硬造公式库。
2. **零猜测红线**：核不到的公式写 `raise NotImplementedError("待核：式xx-xx，p.NNN")`；表值核不准写 `None`；不许用通用教材知识补符号。
3. **页码标注**：每个函数/字典 docstring 末尾 `[核:p.NNN]`，页码以页图页眉为准。
4. **登记表**：每章先交 `handoff-chNN/00-清单.json`（编号式、表、例题的完整清单），再分 A（公式）/B（表值）/C（断言）/D（例题复核）/E（边界勘误）五个子代理。
5. **批次与硬闸**：一批 3 章；**每批结束必须停下等我回「继续」**；状态只许写到「待验收（自检已过）」，「已验收」只能由 Hermes 改。
6. **模型白名单**：把可用模型写死（本次：`deepseek-v4.1-flash`、`gemini-3.8-flash-low/medium/high`、`deepseek-flash`），越界即停。

## 阶段 3 · 执行（ZCode 子代理）

每章按 00 → A → B → C → D → E 推进，`handoff` 全留档（事后验收要靠它反查）。批量 OCR 也交给它：`./ocrbox 某页.png` 是 67 KB 独立二进制，只要有 shell 就能跑（先让它试跑一页确认能执行）。

## 阶段 4 · 执行方自检（不许只交代码）

- 双解释器：`~/.local/bin/python3.12 xxx_tests.py` 与 `/usr/bin/python3` 均 exit 0。
- 断言数 ≥ 编号式数；表字典每张至少覆盖 1 行。
- 自检结果写进进度表，状态写 **待验收**。
- **批闸两侧都要把**：执行方每批停下等「继续」，验收方也按批验、验完一批才放行下一批；验收未过的批不许开下一批（否则未验的章会被后续批次写在前面，验收顺序作废）。

## 阶段 5 · 验收（Hermes 亲自跑，禁止采信自述）

三件套，缺一不算通过：

| 检查 | 命令 | 判据 |
|---|---|---|
| 断言 | 双解释器跑 `xxx_tests.py` | 均 exit 0，断言数与进度表一致 |
| 表值 | `python3 verify_table_cells.py <模块> <表字典> <页图> [--label-idx 0]` | 不一致 = 0（窄列/中文标签的已知局限见脚本 docstring） |
| 例题 | 写 `recheck_<批>.py`：只用库函数 + 书上给定输入，复算书上印的中间值 | 偏差 ≤0.5%，或能指认为书上取整 |

补充两条：**抽查页图**（`sips -c` 裁小区域 → 看/OCR 复核可疑格）；**偏差归因**——书上先圆整再递推（p、δ、η）会让偏差到 1~2%，不算错，但必须在记录里指名是哪一步圆整。

动手验收前先读 `references/formula-library-acceptance.md`：里面是签名/单位陷阱表（十来个已踩过的函数）、偏差四类判据、表值三种 OCR 伪影与裁图修法、zsh `set -- $args` 不词切分的坑。**每个“偏差”先过一遍那张签名表再下结论**，否则会把调用错误报成库的错。

验收记录落 `<工作目录>/验收记录.md`：每章一行（断言数、例题项数、最大偏差、结论），加一节「已知偏差（不是错）」和一节「工具局限」。

## 阶段 6 · 收口

- 进度表 15 章全绿 + 累计断言数 + 累计未核项。
- 技能里记三条：工具在哪、坑有哪些、下次谁干什么。

## 反复踩过的坑（照单避开）

1. **目录页码不可信**：与页眉常差 1~3 页且偏移不恒定 → 逐章标定，勘误留档。
2. **OCR 相邻数字会并成一个 token**（`1.965 2.754`）→ 逐格比对会误报「找不到」，栽图放大复核。
3. **窄列整列漏识**（链表 d1 列）→ `sips` 裁列 + 放大 2 倍再 OCR。
4. **表里的 `None` 必须来自书上破折号/空白**，并在字典 `注` 里说明有几处、在哪几行。
5. **跨页续表要合并并注明**（哪个链号在哪页），否则查表会缺行。
6. **概念章不要硬造公式库**（第1/2/4章）：写 notes，逐式标页，做题时手算。
7. **LLM 逐页抄书不可行**：慢、贵、每次输出不同 → 批量转文字一律用脚本，模型只补难格。
8. **子代理自称「已验收」会污染进度表**：状态词必须由验收方写，否则后面的章会被跳过。

逐章沉淀的全部规矩（7 个子代理分工、handoff 字段、库命名、硬门槛、回执格式、批次节奏）落在两处：骨架与硬条款 `references/dispatch-contracts.md`，可粘贴模板 `templates/book-deposit-zcode-prompt.md`。交给外部 agent（zcode）时**用模板现生成一份、只贴那一份**，不要再拼别的东西。（三本书的历史任务书 `books/<书>/zcode-贴这一份.md`、`dispatch-*.md` 已于 2026-10-26 清理——它们都已完成，别再从旧文件里抄条款。）要点：
- 每章一个库 `mdkit/lib/<book>/<主题>_chNN.py` + `_tests.py`，主题名固定（belt/chain/gear/worm/screw/key/weld/friction/strength/bearing_s/bearing_r/shaft/clutch/general）。

## 章节沉淀：产物是公式库，不是笔记（8 步）

> 自 `SKILL.md` 下沉（2026-10-26 文档整理，正文未改）。

用户说"把这一章的产物回收/让那几小时发挥价值"时，要的是**像 `mdkit/lib/design/gear_ch10.py` 那样的公式库**（式号即函数名 + 表值 dict + 例题断言的 `*_tests.py`），而不是把 wiki 页面读一遍写份总结。写散文页不算交付。

0. **先清场**：上一轮的半成品（该章的公式清单、任何编译/wiki 目录）要么归档后删掉，要么逐条标 `未核`；留着会被下一轮当结论照抄，等于没重做。`raw/`（OCR 源 + 页图）是输入不是成果，保留——重跑渲染 + OCR 要半小时以上。
1. **先 grep OCR 源定位式子**（`grep -n "11-1[0-3]" raw/sources/` 顺带拿到 `## p.xxx` 页码标记），把"式号 → 页 → 页图 PNG"列成清单。文本层抄得出的式子（下标、系数、常数）直接用它，不用读图。**只有公式体被 OCR 打碎的页才读图**（残迹如 `R=及=25`、`dm'z3`、`op-L53KT2`）：一次一页，只问"本页编号公式逐字抄出"。页图定位**先验页眉**——第11章 p001–p028 = 教材页−251，p029–p032 = −252（p.280 整页缺失）；换章必须拿该章源文件 `## p.xxx` 与页眉现算，别沿用上一章偏移。
2. **公式清单先交用户确认**：编号 + 名称 + 类型（校核/设计/中间量）+ 页码，一次列全；同时列出"要用户定的命名/拆分/插值/测试基准"四类问题。
3. **建库**：`mdkit/lib/<book>/<主题>_chNN.py`，函数名 `eqNN_xx`，希腊字母直接用 Unicode，下标用 `_1`；每函数 docstring 写式号/适用条件/符号含义单位。**角度量纲全库定死为弧度**，另给 `度()`/`弧度()`；课本里唯一吃度的式子（如 `Y_β=1−γ/140°`）单独封装成 `螺旋角影响系数(γ_度)`——混两套量纲不会报错只会错，而且每道题错得一样。
4. **已核的写进代码，未核的写 `raise NotImplementedError("(11-13) 待读 p017.png")`**，不许按记忆补符号位置——公式库里一个错的指数，后面每道题都错且 assert 内部自洽查不出来。
5. **表逐格核**：表值另存 dict（`表11_5_KA`），键用课本原词、注释写页码。先带坐标 OCR 拿单元格位置，再裁剪高倍图交 vision 复核；两边不一致时以**坐标重建**为准（vision 在小图上会编读数）。只收录已核实的行/列，未核实的宁可缺。
6. **测试**：用该章例题从已知条件走到最终结果，逐项 assert（容差 ≤0.5%）；设计式与校核式互为反函数再 assert 一次。全绿才算完成。
7. **回写**：范式、符号表、"式号 → 页码 → 页图 → 已核/未核"一起写进 `references/<book>/chNN.md`（一章一文件，别按日期命名）；下一轮从它开始，不重读已核过的页。
8. **核读按页段外包**：整章逐页读图是串行慢活，拆给能读图的子代理并行做（公式段 2–3 个、表值段 2 个、建库 1 个、校验 1 个），每段交一份固定字段的 handoff JSON。任务书模板、handoff schema、验收三关见 `references/sedimentation-delegation.md`。回来自称"核过了"不算数——自己跑测试、抽 5 处翻页图比对、用自造数据反算 3 个式子，三关都过才说"可以调用"。

## 不要为"查条文"去跑编译（2026-10-20 实测）

> 自 `SKILL.md` 下沉（2026-10-26 文档整理，正文未改）。

有人（包括以前的自己）会想"把教材 ingest 成 wiki，以后查得快"。实测代价与收益：

- 一章 32 页 → 编译出 **141 页** wiki，页面总体积是 OCR 原文的 **7.4 倍**（56,620B 原文 → 421,549B 页面）。慢的不是工具，是这 7 倍体积的生成。
- 稳态 4 页/分钟，一章 **25–30 分钟**（不含人工切源）。全量 7 本 ≈ 30+ 小时。
- 而 grep OCR 是 **0.00 秒**，`/chat` 也能直接读从未编译过的 raw 文件并给出文件级引用。

**结论：解题场景不编译。** 编译只在"需要跨章跨书对齐口径"时才值那 25 分钟。vault 里 `机械知识库/wiki/` 已清空、不再生成（2026-10 定）；要重建就按下面三条硬约束来。若哪天真要跑，已知的三个硬约束记在这：源 **≤4KB 且不含大表**（1.6KB 的双栏参数表也会把 analysis 撑爆）；`ingestReasoning: high` 才能拿到 16,384 预算（`maxContextSize` 再大也只有 8,192）；大表先跑 `strip_tables.py` 剥掉表格体。工具与复现步骤在 `~/.hermes/skills-disabled/llm-wiki-desktop`（已停用，没删）。
