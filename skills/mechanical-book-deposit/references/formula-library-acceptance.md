# 公式库验收（一章一库沉淀完之后怎么判“能调用”）

> 适用：`mdkit/lib/<book>/<主题>_chNN.py` + `_tests.py` 落地后，由验收方（Hermes 本人）判定能否给用户调用。
> 子代理/外部 agent 回执里写“核过了/全绿/已验收”一律不算证据。

## 1. 四类证据，缺一不算通过

| 证据 | 命令/做法 | 抓什么 |
|---|---|---|
| 双解释器退出码 | `~/.local/bin/python3.12 <mod>_tests.py`、`/usr/bin/python3 <mod>_tests.py`，两次都要 exit 0 且断言数一致 | 语法/兼容性（3.9 无新语法、无 `math.prod` 之类） |
| 表值逐格 | `mdkit/check/verify_table_cells.py <mod> <表字典> <页图…> --label-idx N --min-nums M` | 表里抄错的数（断言往往只覆盖例题用到的那几格） |
| 例题全链反算 | 自写 scratch 脚本，**只用库函数 + 书上给定输入**，与书上印的中间值逐项比 | 系数抄错但库内自洽、断言也跟着错 —— 只有这一关能抓 |
| 式号覆盖 | 用 `式（NN-K）` 正则抽 OCR 里的式号，与 `dir(module)` 的 `eqNN_*` 对差集 | 整式漏建（`库多` 无意义，OCR 常把式号写成正文，别据此判多） |

反算脚本骨架（别在 notebook 里手敲，写成文件可重跑）：

```python
import importlib.util, os, sys
B = os.path.expanduser("~/.hermes/lib/mdkit/lib/design/")
s = importlib.util.spec_from_file_location("belt_ch08", B + "belt_ch08.py")
m = importlib.util.module_from_spec(s); sys.modules["belt_ch08"] = m; s.loader.exec_module(m)
```

每项输出「书值 / 库值 / 偏差%」，末尾打印最大偏差与通过与否（容差 0.5%，例题本身取整链可放宽，见 §3）。

## 2. 调用前必做：`inspect.signature` + 读 docstring

式号 ≠ 函数名一一对应，相邻式常是并列变体；**传错不报错，只出 1%~2% 的偏差，断言照样全绿**。已踩过的坑：

| 函数 | 真实语义 | 按字面猜会怎么错 |
|---|---|---|
| `eq3_1a(σ_r, m, N_0)` | 返回材料常数 `C=σ_r^m·N_0`，不是寿命 N | 把 C 当 N，差 26 个数量级 |
| `eq3_30(n, N)` | 返回损伤和 `Σn_i/N_i` | 想直接拿到“剩余循环数”，要自己 `N_350*(1-损伤)` |
| `eq12_28(..., p, ...)` | p 单位 **Pa** | 传 MPa 得 9.4e-9 |
| `eq13_4(P, L10, 解="C")` | L10 单位 **10⁶ r** | 传 320e6 得 C=7.5e6 |
| `eq13_18(a_1, L_10m)` | 返回 `a_1·L_10`，求 L_10 要除 | 直接当 L_10 用 |
| `eq8_31(z, F_0, α)` | α **弧度** | 传度，F_p 偏高 1.7% |
| `查表9_7(x)` | x=(L_p−z₁)/(z₂−z₁) | 用 (z₂−z₁)/2π 查，f₁ 偏 1.6% |
| `查表13_5_XY系数` | 必须给 `Fa`+`Fr`（或 Fa/Fr），只给 `Fa_C0` 会抛错 | — |
| `eq5_29` | 只含横向载荷 | 例5-1 那种横向+轴向要用 `接合面不滑移所需预紧力`（F₀ 少 700 N） |
| `eq6_1(T, d, l, h=)` | T 单位 **N·m** | 传 N·mm 差 1000 倍 |

另：表字典里的 `None` 先当“书上就是破折号”，别当漏抄 —— 判法是裁图看（§4）。

## 3. 偏差归因：四类，先分类再下结论

1. **≈0（<0.05%）** —— 通过。
2. **0.3%~0.5%** —— 书取整（z 圆整到 2.89、d₁ 取 8.6）。
3. **0.5%~2%，且能复现** —— **书取整链**：书上先把中间值圆整再往下算。复核办法是拿书上印的圆整值重跑（把 p=2.1979 换成 2.19、把 η=0.0336 换成 0.034），缺口能对上就是取整，不是库错。例7-2 的 δ_min 0.56%、例12-1 的 η/ν 1.2%/1.7% 都是这一类。
4. **成片、成链、方向一致** —— 套错变体/单位，回 §2 查签名。

把 1/2/3 写进验收记录，第 4 类必须回到库改代码。别把“书上取整”讲成“库算错”，也别把第 4 类宽容成取整。

## 4. 表值逐格对不上的三种伪影

`verify_table_cells.py` 报“不一致”，先排这三类再怀疑库：

1. **窄列整列漏识**（清单的 d₁ 列）：一列缺 → 后面每位错开一格，整行全红。判据：库值在页面上别处找得到吗。修：`sips -c 高 宽 --cropOffset y x` 裁列 → `sips -Z 2000` 放大 → `ocrbox`。
2. **相邻数字被并成一个 token**（`1.965 2.754`）：数值其实对，只是 OCR 没分开，工具会报“库值找不到”。看一眼原 token 就知道。
3. **行标签是中文短语**（材料、工况、带型表头）：与 OCR token 对不上，覆盖恒为 0 —— 这类表改用裁图 + `vision_analyze(region=[x1,y1,x2,y2])` 抽查 3~5 格，并把“未逐格核”写进记录。

`vision_analyze` 用小区域裁图问“逐行抄出这三列，破折号写 —”是判 `None` 是破折号还是漏抄的最快办法（整页大图会被问出一堆无关描述）。

## 5. 记录与状态词

- 验收结论写 `~/.hermes/lib/mdkit/books/design/验收记录.md`：一章一行（断言数、例题偏差、表值格数、结论），末尾“已知偏差（不是错，是书上取整）”与“工具局限”两节。**只写结论与命令，不贴大段 OCR**。
- 进度表里的 `✅ 已验收` 只有验收方能写；外部 agent 自填的一律降级为 `待验收`。
- 验收只读不写 `raw/`；发现 OCR 源越界（如第4章文件含第二篇 p.65–67），记进记录并指出“要重切”，不要就地改 raw。

## 6. 脚本里跑循环的坑

macOS 默认 zsh：`for args in "a b c"; do set -- $args; ...` 不会词切分，`$4` 是空的，参数整体错位（表现为 `--label-idx: expected one argument`）。验收脚本的命令参数直接逐条写全，或用 bash 数组，别指望 `set --` 拆字符串。

## 附录 · 原主 SKILL.md 的三条验收陷阱（原样保留）

- **验收公式库：三件套缺一不可**——① 双解释器跑 `*_tests.py` 看退出码（3.12 与 3.9 都要 0）；② 表值逐格核（`mdkit/check/verify_table_cells.py`，见支持文件）；③ 拿教材例题全链反算：只用库函数 + 书上给定输入，与书上印的中间值逐项比，容差 0.5%（书值圆整造成的 0.3%~0.5% 偏差正常）。例题反算是唯一能抓住「系数抄错但库内自洽、断言也跟着错」的一关，表值全对不等于公式对。式子可能是读图核的、表值是坐标 OCR 核的，只抽其中一半等于没验另一半；优先抽设计落点表（`表11-1` 这类）与承载能力链。验收完把库搬进 `mdkit/` 当唯一版本，并改掉 references 里的旧路径。完整判据、偏差归因四类、表值伪影三种与状态词规矩见 `references/formula-library-acceptance.md`。
- **例题反算出来的偏差先归因，再下结论**：0.5%~2% 的差常常是**书上取整链**（书上先把中间值圆整再往下算），拿书上印的圆整值（p=2.19、η=0.034、ν=38）重跑一遍，缺口闭上就不是库错；成片成链、方向一致的偏差才是套错变体/单位，回 `inspect.signature` 改调用。两类混着报，用户会以为库坏了。
- **表值逐格核出来的「整行不一致」先怀疑 OCR，不要先怀疑库**：全页 OCR 会整列漏识窄列（如链表的 d1 列），那一列一缺，后面每个数都错开一位，工具会报整行全错。判据是「库值在页面上别处找得到吗」；真漏识就把该列 `sips -c 高 宽 --cropOffset y x` 裁出来 `sips -Z 2000` 放大再 `ocrbox`，窄列放大后基本都能识出（实测 d1 列 10.16/11.91/12.07 全出）。行标签是中文短语的表（材料、工况）与 OCR token 对不上，覆盖会一直是 0，只能人工看图。

## 图上系数（曲线）的落库与先验约定

> 自 `SKILL.md` 下沉（2026-10-26，正文未改）。

**同一材料名在不同图上就是两条线，先验必须连图号一起记。** 「图上系数」的先验常被写成「材料 + 硬度 → 值」，缺图号就串图：实测 `σ_Hlim` 图(b) 的先验（正火低碳锻钢 ME 130HBW→448）被拿来核 `σ_Flim` 图(b) 的读数（130HBW→394），差 13% 看着像标定错了，实际是两张图两条轴。核之前先对图号 + 横轴单位（HBW / HV / HRC 不能混），对不上就当两回事，别急着否定对面的读数。

**曲线落库的三个约定**：① **折线要分段存**——一条线在某个硬度拐弯（实测氮碳共渗钢 ME=MQ 在 ≈449 HV）时，单组 `(k, b)` 表示不了，用 `[[k, b, 该段上端硬度], …]` 加一个求值函数（`_线值()`），同时对单段写法保持兼容（新老条目共用一个查函数，别另开一套）；② **「带内取值比例」这类经验系数，有例题锚点就反标定、没锚点就按书上原话取中点并在元信息里显式声明「无锚点、取 0.5」**——同一张图里带锚点的材料可能是 0.336，两套口径混写就是一个数冒充两个来源；③ **子代理自评 `partial` 的段要逐材料/逐线分级合并，不要整段收也不要整段丢**——把读数干净的那几条（ML=MQ 拟合 rms <1 MPa、线端与网格不相切）按 verified 入库，只把有疑点的那一条挂着继续 `NotImplementedError`，并在元信息里写清「哪条、差多少、为何不进判据」（例：球墨铸铁 ME 线端与 500 MPa 网格相切，标注反算 526.6 vs 线端 501.6，差 +5% → 该 ME 只作参考）。整段退回会把另外几条白读一遍；整段收下则让一条可疑线变成全库默认值。

## 已知技术债：跨章复制的私有 helper（2026-10-26 审计）

`_区间` 在 design 侧 6 个章库各有一份、`_格`/`_表` 在 handbook 侧 10 个章库各有一份、`_自检`/`_数` 各 9/7 份——
都是抄上一章开工时带过来的。**不要为了"统一"去重写已验收的章库**：2,123 + 1,896 条断言锁的是数值，
抽 helper 会让 diff 铺满全库，收益只是好看。

新章的做法：先在 `lib/<book>/` 里 grep 已有的同名私有函数，照抄**已验收**那一份的实现（连同它的边界处理），
别自己写第三版；真要共享就写新模块 `_util.py` 并只让**新章** import，老章不动。
