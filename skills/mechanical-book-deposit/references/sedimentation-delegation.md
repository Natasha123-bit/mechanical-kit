# 把一章的核读外包给子代理

适用于"整章 20+ 个式子 + 10–20 张表要逐格核"的沉淀。串行读图是几小时的活，按页段并行能压到一次会话内。

## 角色划分（上限 7 个，边界别重划）

| 角色 | 范围 | 交付 |
|---|---|---|
| A | 公式·前半章（参数体系、几何尺寸、运动关系） | handoff/A.json |
| B | 公式·承载能力（受力、接触、弯曲、刚度）——**最重要，逐字核** | handoff/B.json |
| C | 公式·后半章（变种型式、效率、热平衡） | handoff/C.json |
| D | 表值·参数表（设计落点那张整表要可用，如 m 与 d₁ 配对） | handoff/D.json |
| E | 表值·材料与系数表（每格必须带行头列头） | handoff/E.json |
| F | 建库（读齐 A–E 才开工） | `worm_chNN.py` |
| G | 校验 + 回写 skill（**不外包**，主代理亲自做） | tests + references 文件 |

## 表型书（手册/标准汇编）的角色改法

公式型按「式子段落」切；表型书没有式子，按**页段**切，并把判据与标注拆成独立角色（否则子代理只会抄表，不会把表变成能用的答案）：

| 角色 | 范围 | 交付 |
|---|---|---|
| B1 | 表值·本章前半页段（逐格核，续表合并） | `handoff/B1.json` |
| B2 | 表值·本章后半页段 | `handoff/B2.json` |
| C | 判据函数：读齐 B1/B2 才开工，按任务书的「绘图问题清单」写 L2 | `handoff/C.json` + 库内 L2 段 |
| D | 标注复现：用 L2 + `_anno` 复现第20章零件工作图的标注 | `handoff/D.json` |
| E | 边界勘误（章首章末、混入别章的表、清单里无页的表号） | `handoff/E.json` |
| F | 建库整合 + 双解释器 + 回执（**主代理自己做**） | 库 + `_tests.py` |

串行闸：章内 B 没核完 C 不开工；章内自检没绿不开下一章；整批没验收不开下一批。
`confidence != verified` 的表只能写成 `raise NotImplementedError("待核：表x-y，p.NNN")`。

## 任务书必须写死的七条

1. **材料清单给绝对路径**，含页图目录与"页图序号 ↔ 教材页"偏移算法（现算：拿首个 `## p.xxx` 标记与 PNG 号求差，换章重算）。
2. **已知缺口明写**（哪一节没有 OCR 源、哪几页只有扫描图），否则子代理会假设它不存在。
3. **零猜测**：核不到的式子只写 `raise NotImplementedError("待核：式NN-x，p.NNN")`，禁止用通用教材知识补齐符号位置；表值核不准的格写 `None`，禁止插值凑数。
4. **docstring 带出处**：式号、适用条件、每符号含义与单位、`[核:pNNN]` 或 `[未核]`。
5. **只读边界**：原文目录 `raw/` 只读、不动已落地的公式库、不在教材库做 git commit、产物不写进笔记库。
6. **环境**：纯标准库、两个解释器都要跑通、模型白名单、不留密钥。
7. **验收只认证据**（见下）。

## handoff JSON（字段固定，一个不许少）

```json
{"kind":"formula|table","ref":"式(NN-9)","page":265,"png":"p014.png",
 "latex":"...","symbols":[{"sym":"T_2","mean":"...","unit":"N·mm"}],
 "conditions":"...","how":"vision|坐标OCR+高倍复核",
 "confidence":"verified|partial|unverified","notes":"OCR 残迹对照"}
```

表值项额外带 `rows`/`cols`，`latex` 置空。`confidence != verified` 的项，F 只能写成 `raise`，不许写成可调用函数。

## 前置提示词（贴给外部代理的第一段）

1. 先读任务书路径，按它执行，不确认背景、不扩大缩小范围。
2. 三条开工动作，各回一行：`ls` 全部材料并报缺口（桌面路径可能被 TCC 拦，读不到就复制进工作目录）；**声明子代理是否具备视觉能力**（能 → 读页图逐字核；不能 → `ocrbox.swift` 坐标 OCR + 高倍裁剪复核），先定再派活；按角色派活并在 LOG 里逐行留痕。
3. 复述硬约束（零猜测、只读、不装依赖、模型白名单、不留密钥）。
4. 回执按固定格式：结论 / 产物（行数、函数数、断言数）/ 测试命令+末五行+退出码 / 例题逐项对比表 / 抽查 5 处 / 未核清单 / 能否直接调用。

## 验收三关（主代理自己做，不采信自述）

1. 跑 `python3 *_tests.py`，退出码 0。
2. 随机抽 5–6 处入库式子或表值，翻开对应页图比对。**抽样要跨核对方式**：公式段多半是子代理 vision 核的、表值段是坐标 OCR 核的，只抽公式那一半等于没验表。优先抽设计落点表（本章最贵的那张）和承载能力链上的式子。
3. 用与例题无关的自造数据反算 3 个式子（容差 1e-9）。
4. **收尾装库**：库若落在交付目录，验收时搬进 `mdkit/`（唯一版本），改掉 SKILL.md 与 references 里所有指向旧路径的行，再在新位置重跑测试；两处副本并存，下次改一处漏一处。

再加一条旁证：看 `LOG.md` 有没有逐页证据（谁、读了哪页、核了什么、结论）。三关有一关不过就说"不能调用"，并说清缺哪块——不要用"基本正确"代替结论。

## 坑

- **子代理读不了图却不声明**：它会把凭印象写的式子标成 verified。派活前就要它回答这个问题。
- **一次 vision 只问一页、只问"本页编号公式逐字抄出"**：问全页会拿回大段无关描述；页数多时先报张数让人决定要不要这么做。
- **大表别靠 vision 读数**：坐标 OCR 拿格位 + 按坐标裁高倍图复核，两边冲突以坐标重建为准。
- **交付目录当成了最终位置**：子代理习惯把库写在交付目录、让 references 指过去，验收时不搬不重跑，下次就在两处副本之间漂移。
- **量纲混用**：常见于子代理建库——一部分入口吃度、一部分吃弧度，各自 assert 都对，串起来算就错。验收时逐个入口看 docstring 有没有写死单位，缺转换辅助就自己补，补完重跑测试。
- **别让它顺带建 wiki/编译**：一章 25 分钟起，而且公式页编译出来是 `verified: false` 的空壳，等于白花。
