# 机械设计/机械原理作业（例题范式计算书 + 国标零件图）

一份 SKILL.md 只放**跨章通用**的内容：入口、交付形态、流程、书在哪、取值路径、章目录、通用陷阱。
**一章的全部知识在 `references/<book>/chNN.md`**（解题步骤 + 式子 + 表值 + 例题证据），做题时只读那一章。
公式库与工具真身在 `~/.hermes/lib/mdkit`（作者本机这里是指向项目目录的 symlink，绝对路径照用，布局见 `mechanical-book-deposit/references/version-control.md`），是 git 仓库（origin = GitHub `Natasha123-bit/mechanical-kit`）。改动在原位直接 commit；`draw/**` 下的 svg/pdf/png/html 被 `.gitignore` 排除，往 `draw/` 里放的样例图不会出现在 `git status`——要入库得先加 `!draw/<子目录>/样例-*` 例外，报告时把这件事说清楚，别让对方以为文件没落地。**不要再做手动备份，也不要复制交付物/样例图进 skill 目录**——但 skill 自身的文件有两份：`mdkit/skills/mechanical-homework/**`（进 git、要 push 的那份）与 `~/.hermes/skills/engineering/mechanical-homework/**`（agent 实际读取的独立拷贝，不是 symlink）。改完 `cp` 同步并对两份 `diff -q`，只改一份＝改了没人读的那份。落点、访客安装方式与公开版口径见 `mechanical-book-deposit/references/version-control.md`。

## When to Use

- **单题**：用户在聊天里贴了题目截图/题目 PDF，要求做某道计算题（齿轮传动、蜗杆传动、轴、轴承、螺栓组、带/链传动…）→ 走下面「流程」，按章读 `references/<book>/chNN.md`。题目在哪不影响交付目录，一律落到下面的默认路径；用户明确指定了别的目录才改。
- **要求按课本例题范式写**：要"按例题那样一步步写"、公式一个不省、取值处注明表几图几 → 见「交付形态」。
- **要成品**：要可打印的计算书（A4）+ 零件图（**A4 横放 1:2**），或要校验图是否符合国标 → 走「流程」5–6 步 + `references/gb-gear-drawing.md`。
- **整机课程设计（减速器设计说明书）**：给一组题目数据（卷筒转矩/带速/卷筒直径…）要 11 节完整说明书（电动机→传动比→齿轮→轴→轴承→键→润滑→箱体）→ 走 `references/reducer-design.md`（骨架、尺寸链闭合顺序、判据、四张示意图），公式仍按章读 `references/design/chNN.md`。**带传动 + 一级圆柱齿轮与二级两种链条都在该文件（§二·六 是单级变体）；第一轮只交「参数确认单」（§一·五），等用户签字后再写 11 节正文。**
- **审阅/复核已写好的说明书**：自己写完请人审、或用户贴来另一个 AI 的审计结论要求“校验是否属实” → 走 `references/design-review-audit.md`。先渲染页核“缺字/错字”，再按轴系结构、力学、文字三组判真伪；外部审计说的“表5/表8 缺数据”多半是 PDF 提取假象，照单改会改坏。
- **只核对字母代号/符号与教材口径**（“设计书第七章代号好像跟书上不符”“告诉我替换字母”）→ `references/design-review-audit.md` 的 **§9**：只交一张对照表（现用 → 教材用 → 含义/页码），不重出计算过程；扫描件下标判不出就标**未核**请对方翻页，不许把推测列成“待替换”。
- **整章 / 多题**：一次给整章习题 → 同一章文件反复用，别重读；跨章题（如轴 + 轴承）按依赖顺序读两章。
- **只出图 / 改图**：参数已定，只画零件图或按参考图改版式 → 直接走「流程」5–6 步。
- **问制图教材的某条规定／图面尺寸**（标题栏、明细栏、图框、幅面、字号、填写顺序）→ **不画图**：先查 `references/drawing-book-ast.md`「标题栏 / 明细栏 / 图框的固定数字」，命中就直接答并补页码/图号；这些数**与幅面无关**（恒 180 宽），不许按 A1/A0 类推「放大」，也不许凭记忆报。用户接着说「把那几页书截图发我」= 从全书 PDF 渲**整页**发，别发裁切图（页码换算与渲染命令见 `references/books.md`「把教材某几页发给用户」）。
- **沉淀整本书**（"把《XX》整本沉淀""整本教材沉淀成公式库""走上次那套流程"）→ **不在这里**，走 `mechanical-book-deposit`。
- **第二本书起**（机械原理等）结构完全一样：只多一段「图解法作图步骤」，见 `references/books.md`。
## 书在哪（通则 + 例外下沉）

书清单在 `references/books.md`，**加书只改那里**（一行 + 一个 `book.md`），本文件不动。
标准件（轴承/键/联轴器）的**尺寸与 C、C₀ 不在教材里**，在《机械设计课程设计手册》（纯扫描件、无文本层）：定位法与页码换算见 `references/books.md`「标准件数据源」。

每本书（`<book>` = `design` / `mechanisms` / …）统一命名：

表里的**「知识库根」= 用户自己放知识库的那一层目录**（页图与 OCR 源都在它下面；目录由用户自定）。

| 东西 | 位置 |
|---|---|
| **全书 PDF** | 一题一本，路径登记在 `references/<book>/book.md`；原始件，不拆不删 |
| 章 PDF（临时） | `~/.hermes/lib/mdkit/books/<book>/_split/chNN-<章名>.pdf` —— 渲完页图即可删，`mdkit.py prepare --split-only --only N` 随时重建 |
| 页图 | `知识库根/raw/assets/<book>/chNN/p001….png`（三位零填充 = 章内第 k 页） |
| OCR 源 | `raw/sources/<book>/chNN-全章OCR.md`（每页 `## p.印刷页` 标记） |
| **章知识** | `references/<book>/chNN.md` —— 解题步骤 + 式子 + 表值 + 例题证据，**一章一文件** |
| 公式库 | `mdkit/lib/<book>/<主题>_chNN.py` + `_tests.py` |

**例外写到各书 `references/<book>/book.md`，不写这里**（页码偏移、缺页、错位块、未渲染的章）。

## 交付形态（默认就这么给）
- **格式按人类作业写**：`已知 → 解 → （1）（2）…` 分步；公式一个不省，但每步只写「取/查/算」，不写解释性白话、不写过程叙述、不写小结。参数取值处一句话说明依据（表几/图几）。**排版照教材例题范式**：黑字单栏、无卡片色块边框、公式独立居中且代入数值与结果同在一行、**右侧不标公式编号**、表格用纯线表、结尾「说明」①②③、无页码；用户甩一份参考 PDF 说「格式以这个为参考」时抄的是版式。细节、CSS 骨架与像素校验见 `references/calc-book-layout.md`。
- **落盘**：作业根下的 `<题号>解答/`（作业根 = 用户自己放机械作业项目的那一层目录）——**一题一个目录，`<题号>` 按本题换**；**教材例题的编号带「例」字**：目录写 `例13-1解答/`、标题写「例13-1　深沟球轴承的选择」，不许简写成 `13-1`——章末习题 13-1 与教材例题 13-1 是两道不同的题，混写会串题，用户核对时第一眼就会指出来。开场第一件事 `mkdir -p` 再 `cd` 进去，后面所有命令都在里面跑；**不许复用上一个题的目录**（复用一次就是两个题的产物混在一个文件夹里，事后分不开）。同名目录里已有别的题号的东西时停手报告，不要往里写。
  - **同级若还有别的项目目录（制图练习、课程设计、旧题改版等），先读归属记录确认它不属本题再动手**：目录名相近不等于同一份东西；报「哪张图、属于哪个题」之前先查归属清单——不凭目录名、不凭上轮对话、不凭记忆推断（把 A 项目的图说成 B 题那张，是这类串题的典型）。归属记录若是脚本生成的，改表要改脚本再重跑，手改会被下一次重跑覆盖；写盘后把记录自己的 mtime 一并回填，否则「清点时间 / 本文件时间」自相矛盾。
  - **中间产物一律进 `_tmp/`**：`mdkit.py page` 的页图、裁图复核、`_校验图像`、`__pycache__` 全放 `_tmp/`，交付前 `rm -rf _tmp`；**重跑校验不必先删**——`mdkit.py page` 直接覆盖同名 PNG，链式命令里带 `rm -rf` 只会平白卡一次审批确认。根目录只留交付物（PDF/md/svg）、源脚本、资产（`fonts/`、`katex/`）——11-3 那次根目录堆了 71 张过程图 + 4 个 png 目录，93 个条目，用户打开就炸。
  - **源按交付物分两类**：纯文本计算书 → `计算书.md`，跑 `mdkit.py book 计算书.md --pdf`（转换器与 CSS 在 `mdkit/templates/book/`，HTML 只是可删的中间产物）；要画示意图的题（受力分析、机构简图、图解法、轴系结构）→ 源就是 HTML + SVG（KaTeX CSS 与字体随目录拷，离线可开）。零件图一律 SVG（1 单位 = 1 mm）。别给计算书再手拼 HTML——手拼那版今天就漏出过 `\,` 和 `\qquadF`。
  - **图幅与字体**：A3 会被嫌“图纸太大”，别默认 A3；图面文字按标准字号（尺寸 3.5、小字 2.5）不随比例缩放，标题栏比例栏写实际比例。**图面汉字用仿宋**，字体栈把 `FangSong` 排第一位（`~/Library/Fonts/Fangsong.ttf` 的真名；把 `STFangsong` 排前面 Chrome 会静默解析成 STSongti 宋体），别留系统默认的 PingFang/宋体/黑体——落地与验法见 `references/svg-pipeline.md`「字体落地」。
  - **多题一次交付**：每题一个目录 + 各自一个生成脚本（`build_13_1.py` 这类，别用一个脚本同时写三份），每题单独跑 `mdkit.py book`；回话里按题一条 `MEDIA:` 分开发，不要拼成一个 PDF 或压 zip（用户说「把三个计算书发我」要的是三份）。三份都出完再一起报，每题给一句结论数。
- **交付必须含图纸 PDF**：`ls 目录/*.pdf` 有、页数 1、MediaBox 对得上、能栅格化回读——只有 SVG + `print.html` 不算交付（用户会直接问「pdf 不出了？」）。**改图之后同样要重出**：生成器只写 `.svg` + `print.html`，PDF 是单独的 Chromium `--print-to-pdf` 一步；只跑生成器就报「改好了」＝用户打开的还是旧图，用户会说「你只改了 svg」。判据是 PDF 的 mtime 晚于 SVG，再渲第 1 页裁一眼改动处。出法与核法见 `references/svg-pipeline.md`「五」。
- **用户说「桌面放一份」= 复制，不是移动**：`cp` 到 `~/Desktop/`，正本留在归档目录；桌面那份是临时查看点，用户说归档/清理时删副本、归档目录不动。副本名带题号（`11-3计算书.pdf`）。用户不说就不主动往桌面放。
- **交完就清，清前先打捞**：用户说某次作业「已交、可以删了」时，先扫一遍有没有下次还要用的东西——程序化出图脚本（`gear_draw.py` 这类，一千多行的参数化管线）、KaTeX 字体、一张成品图当版式样例——移到 `mdkit/draw/` 与 `mdkit/templates/katex/` 再整体删。成品 PDF、题目截图、课本副本属于当次成果，跟着删。报的时候分开说「删了什么」与「打捞到哪」，只报「删了多大」会让用户怀疑代码一并没了；反过来，题目截图和已交成品别自作主张留档。
- **交前自检**（用户会逐项核）：尺寸链是否闭合、结构形式判据是否用对、每个查图/查表取值是否说得清、前提假设是否点明。再加一道**跨文件互校**：计算书正文里写到的每个表面粗糙度、配合代号、结构尺寸，图上必须能一一对到（书写了"端面 Ra3.2"，图上就得有这处标注）；图上参数表逐行对计算书的结构尺寸表，別只对模数齿数。

## 开工前：先定范式、先定预算

**要画图 / 改图 / 跑闸，先读 `references/work-loop.md`**（参考件读法、轮次纪律、自检与验收的边界、闸的调用与盲区、查接口）；本节只留动手前的硬约束。

- **题面/老师要求偏离手册时：照做，但只落在项目里，不许把偏差写成 skill 或套件**。典型是功率口径——手册与教材按**输入功率**逐级递推，题面可能要求把联轴器、卷筒的损失并进末轴（输出口径）。这时：①链条只改 `calc/` 里的 `s0`、`s1` 两处，下游 `s2~s5` 全部重跑（图是 JSON 驱动就自动跟着变，别手改 SVG 数字）；②说明书里写「按任务要求采用××口径」，把归属说清，读者才分得清这是被要求的、不是设计选择；③不进构建的旁路副本（`00_参数确定.md` 四轴表/`T_ca`/`F_t`、图纸 `calc.json` 的 `校核` 块）同批改，并加一条新版本头；④定量说清偏差方向再交付——换成更宽松的口径，轴、键、轴承的应力与寿命整体往偏小偏安全的方向挪（实测 1%~4%），别把它当正常结果报；⑤**不把这条链、这套换口径步骤写进 SKILL.md 或 references，也不给 mdkit 加功能**——它是题面特例，写进 skill 下次会被当范式复用，用户会当场要求撤掉。收尾前 `grep <当天日期> ~/.hermes/skills/.curator_ledger.jsonl` 核一遍：后台 curator 会在会话中途往本 skill 写条目，凡带本次专有数字或口径词的删掉（账本只存 sha256、不存原文，只能按内容 grep 定位后逐条删）。
- **第一版动手前先要范式**：要两份参照——计算书参考件（一份真实例题解答 PDF/截图）、零件图参考件（教材图例或用户以前的作业图），一句话问「照这个排，可以吗」。没参照就先说默认口径（教材例题范式 + GB 简化标题栏 + A4 横放），等一个字再开工。**别自拟版式**：自拟等于盲做，一张图一轮返工就能吃掉整份作业的时间；用户手里基本都有范式图，问一句比返两轮便宜得多。
- **先问参考件的适用边界**：用户说「除标题栏外按这个来」，就一个格子都不许动标题栏（含图号、格数、有没有比例栏）；参考件里用户没点名的部分（标题栏、图签、栏格）保持既有版本。擅自「按 GB 补全」＝改了用户规定以外的东西。
- **预算**：单份作业（计算书 + 一张零件图）目标 ≤20 分钟。**vision 不是验收工具**：图像已走原生通道（0.02 s/次，判定链见 `hermes-provider-config` 的「Image input」节），速度不再是理由，但它**会编读数**——594 px 缩图上 `46` 读成 `16`、`φ25` 读成 `φ40H11`。所以：题目/范式图读一次、交付前整页观感 1~2 次，其余「有没有这条线 / 压没压线 / 数字对不对」全部走坐标断言、像素探针、生成文本 grep；要读图上小字就传 `region` 裁切，别整页缩图。
- **探针写在出图之前**：先把该量的坐标、线位、留白、字数列成断言，再出图跑断言；不是出图→截图→问 vision→再补探针。
- **分段报时**：算完 / 计算书出 PDF / 图纸出 PDF / 按意见改完，各报一句「还剩什么、大约还要多久」；超过 40 分钟没交付主动报卡点，让用户能叫停。

## 流程
1. **读题**：`vision_analyze` 看题目图片，逐字取全部数据（含表格、图注），不要凭记忆补参数。**上下文摘要/上轮结论里的参数也不可信**：出图前回 `解答.html` / PDF 原件 grep 一遍模数、齿数、齿顶圆、精度等级（`m=2.5、z₂=54、d=135` 这种只要一个数错，参数表、标题栏、所有尺寸会一起错，而且 check 内部自洽查不出来）。
2. **取课本范式**：先跑 `mdkit.py probe 书.pdf` 探针（页数 + 逐页 `chars` + 首行字符），判断文本层能不能用：纯扫描页 `chars=0`，坏 CID 的页会吐出 `W-tiWlW`、`$n[^I io-5` 这类乱码，PDF 里 `/Font` 对象多寡不能当证据。文本层可用才 grep `例`、`表10-`、`图10-` 定位例题与表格；不可用就整册走 `mdkit.py ocrpdf 书.pdf 首页 末页 输出目录`（macOS Vision OCR，中文识别准）。同一本书两卷可能不一样：实测《机械设计》第10章 PDF 有字但全是 CID 乱码，《机械制图》（331 页 Z-Library 版）是 0 字符纯扫描——每本都要探，不能凭上一本的结果类推。
3. **算式按该章的解题步骤**：顺序见 `references/<book>/chNN.md` 的「解题步骤」，不许跳步（齿轮那种"试算→修正"两遍 K，跳过修正会被一眼看出没按范式）。
4. **查图系数**：见 `references/textbook-chart-reading.md`（扫描图上的曲线要标定坐标读，别估）。
5. **出零件图**（**画图前先读 `references/work-loop.md`；画图/跑闸一律不许自拟检查器**）：见 `references/gb-gear-drawing.md`（线型、参数表、标题栏、公差、版面）；**A3 单张图与 gbdraw 的坑见 `references/part-drawing-a3.md`**；**画轴类零件图或改已有的轴图，先读 `references/shaft-part-drawing.md`**（不剖主视图 + 移出断面、分区公差表、基准 A/B = 轴承颈、键槽标法、**定位轴肩上下限**、**技术要求追加排在最后**——改图被退回的三次都栽在这两节写着的规则上）。图要反复改参数就写程序化管线（参数 schema → render → check → PDF/PNG），见 `references/svg-pipeline.md`，别手改坐标。
   **出图就接闸，别等交付**：图元走 `SemSheet`（`lib/drawing/sem.py`，`R(role, view=, name=, feature=, elem=)` / `G()` 包一组），每个图元带 `data-role`，轮廓再加 `data-view`/`data-feature`；生成器在同一次运行里把轮廓导成 `features.json`（同源同变量，y 翻转成向下）、把参数导成 `calc.json`。**改图前先把当前版 `cp` 进 `_bak_<改动名>/`**（用户说「效果不好我随时要求回滚」时，回滚成本要压到一条 `cp`），交付时一句话给回滚命令。用户甩参考图并说“只改数据”时：抄它的**版式**（视图名写在图下、参数表栏目、直径引线、键槽标法、技术要求措辞、投影法符号——**标题栏除外**，见 `references/shaft-part-drawing.md`「标题栏」），换**数据**，但**结构形式按本题 d_a 判据**决定；与参考图不一致处主动说明原因并给出改法。
   **参考件是 SVG 就先读源码再动手**：带 `data-role`/`data-name` 的 SVG 等于一份可执行规格（outline / hatch / cutting-plane / tolerance-frame / datum / section-outline），能直接量出符号尺寸（公差框 22×6、箭头 2.5×0.9、基准框 6×6）与几何关系（断面缺口朝右、剖面线端点落在边界上）。位图只能看出「有这条线」，量不出「几毫米、朝哪边」——先把元素按 role 列一遍再写图，比截三次图猜快得多。
6. **出 PDF**：CDP `Page.printToPDF`，`preferCSSPageSize=true` + `printBackground=true`；A4 用 `@page size:A4`，A4 横放写 `@page{size:A4 landscape;margin:0}` 并置 `paperWidth=11.693, paperHeight=8.268`（A3 横放则 16.535/11.693）。base64 直接写盘。计算书里插横放附图用 CSS 命名页，别转图：`@page figpage{size:A4 landscape;margin:8mm 10mm}` + `.figpage{page:figpage}`，图片给 `max-height:174mm`，否则会溢到第二张横放页。
7. **校验（先跑闸，再量像素）**：**跑闸前先读 `references/work-loop.md`；不许自拟检查器**。跑的永远是 `charter/check.py`，闸的调用与盲区见该文件；图面验收只认全参 `charter/check.py`（`--part gear|shaft --calc --features --fig-no`），按它报的 ✗ 与「未检查」清单逐条改；「未检查」也要在交付里点名，别当成通过。闸覆盖不到的才用像素补：`mdkit.py page 图.pdf 输出目录` 把 PDF 逐页转 PNG。**几何校验不调 vision**：`mdkit.py check 图.png --page 297x210 --scan y=85 --scan x=75`，把检出线位与理论值逐条对（齿顶/齿根/孔壁/剖面线范围/端面是否落在 X0、X1）。vision 只在交付前做 1~2 次整页观感确认，只核“有没有压字 / 重叠 / 缺行 / 被裁”；它在缩略图上会编读数（φ25 读成 φ40H11、65 读成 50），数字与线位一律别拿它当依据，读小字用 `region` 裁切。取样时探测列避开中心线（点画线的 dash 会给假读数）、墨量带避开线本身 ±0.4 mm。

## 常用校核式
- d_a=d+2m；d_f=d−2.5m；h=2.25m；a=(d₁+d₂)/2；s=πm/2
- 公法线 W_k=m·cosα[π(k−0.5)+z·invα]，k≈z/9+0.5 取整（z=54 → k=7, W=49.86），inv20°=0.014904
- 键槽（GB/T 1095，按孔径查区间，别沿用上一题）：22<d≤30 → b=8、h=7、t₁=4.0、t₂=3.3（φ26 → 毂槽深 29.3）；44<d≤50 → b=14、h=9、t₁=5.5、t₂=3.8（φ50 → 毂槽深 53.8）；d=25 → 28.3。**毂槽深 = d+t₂**，绘图时 `R_KEY = Rw(bore/2 + t₂)`，不是 `Rw(毂槽深/2)`。**键长 = 轮毂长 −(4~6) 取 GB/T 1096 标准值**（84→80、48→40；72 落 66~68 但序列只有 63/70，取 63），剖面不许小一号或大一号。**4~6 是经验值，不是取值目标**：轴伸短于轮毂时基准换成轴伸（联轴器 Y 型孔 112 配轴伸 100，键仍取 **80**、居中两端各 10——工作长 68、σp=82.9 MPa 已满足，为凑经验值拉到 90 只是把轴上的键槽拉长）；**加长键只有一个正当理由：校核值逼近许用、要用更长的工作长度换余量**（大齿轮轮毂 72 配 56 时 σp=95.5/100，加到 63 降到 81.8）。轴端缩进孔内时挡圈装不上，改由轴肩定位——理由与 σp 对照见 `references/shaft-part-drawing.md`「键长怎么定」
- 轴径估算 d≥C·∛(P/n)，45 钢 C=112，有键槽再放大并取标准值
- **轴承肩三头受夹，表 6-1 两列方向相反**：直径 ≥ `d_a`（**下限**：6207=42、6209=52）、直径 ≤ 内圈外径（≈d+0.31(D−d)）、**肩圆角 ≤ `r_as`（上限：6207/6209 均 1.0，且小于轴承倒角 `r_s`=1.1）**。圆角按一般轴肩取 R1.5/R1.6 就是内圈骑在圆角上、端面贴不实，而直径段长全对、闸也不判——轴承肩一律 R1，非轴承台阶才用 1.5/R2，详见 `references/shaft-part-drawing.md`「定位轴肩」。

- `templates/book/` —— 计算书 Markdown → PDF：`md2html.py` + `book.css`（版式唯一真源）+ `katex_render.js`；`templates/katex/` 自包含
- `draw/gbdraw.py`（GB 图元，1 单位 = 1 mm，`--selftest` 5 项）、`draw/mech_frame.py`（说明书插图，见 `references/mech-frame.md`）
- `lib/drawing/charter/devloop.sh` + `devloop_crop.py`（在 mdkit 里，不依赖项目目录） —— 改图循环：build → check → 整页截图 → 按 `data-view` 裁局部，一条命令出全部预览图；交付 PDF 仍归 `build.sh`（细节见 `references/svg-pipeline.md`「六½」）
