# 设计说明书复核（外部 AI 审计真伪核对）

## 何时用

- 用户写完减速器/机械设计说明书，要求“看看有什么问题”“打分”，或贴来另一个 AI 的审计结论要求“校验它说得对不对”。
- 目标是**核对证据**，不是重做整套设计；只有发现影响装配/强度/规范的硬错，才给改法和重算范围。

## 0. 先定边界

- 用户说“本轮不要改任何文件”时，只读。临时渲染、裁图、文本提取一律写 `~/.hermes/cache/scratch/<task>/`，结束清理；不要写项目里的 `_tmp/`，更不要改交付物。
- 交付分四级：**真问题 / 半真（现象对、结论过重）/ 不属实（提取假象）/ 不是错误（取舍或简化）**。每条给页码、表号、格子或实算值。
- 不复述整份设计；先给一句总判断（哪份审计更可信、哪几条必须改），再展开。

## 1. 三条证据链，缺一不可

| 链 | 取法 | 用途 |
|---|---|---|
| 渲染页 | `mdkit.py page 说明书.pdf <scratch>` → `p001.png…`；`vision_analyze` 必须给 `region` 裁到表格/封面/参考文献 | 判“表里到底印了什么”、版式、罗马数字、括号 |
| 文本层 | `mdkit/bin/pdftextlayer 说明书.pdf <pageIndex>`（只给样本行）；整页用 Swift PDFKit `PDFDocument` + `page.string` | 判“文本层有没有这个数”；有字≠行列对 |
| 源与数值 | `设计说明书.md`、`设计说明书.html`、`calc/s*.json` | 对表值、公式、取整、效率链 |

三者不一致时，**先怀疑渲染/提取，再怀疑内容**。外部审计的 PDF 解析经常在跨页表、居中数字列、罗马数字、下标上出错。

## 2. 四类“它读错了”（高发假象）

1. **跨页续表**：表在页底断开，下一页顶部接着 Ⅶ/Ⅷ 行但没重复表头。只读上一页会得出“漏两段、合计差 29”。核法：列长逐项相加 vs 表末总长；差额正好等于下一页行数时，翻页。HTML 里 `<thead>` 为 0 时浏览器不重复表头，这是排版缺陷（可建议 `thead{display:table-header-group}`），不是数据缺失；**不要“补数据”**。
2. **居中数字列首位被截**：`93.94→3.94`、`451.06→51.06`、`442.08→42.08`。三个数都恰好少首位，是列边界截断的典型样子。核法：裁切渲染页 + PDFKit 文本层。
3. **罗马数字/下标误读**：Ⅱ 读成 I、Ⅷ 读成 Ⅶ；`F_t/F_r` 读成 `F1/F1`；`i带/i齿` 读成 `i⊥⊥`。核法：裁切原图看字形；HTML 里通常是 `F<sub>t</sub>`、`i<sub>带</sub>`。
4. **版式误判**：封面“学　　校”是两个全角空格的对齐写法，不是“校”字跳到行末；参考文献 `[6]`/`[7]` 的左右括号在渲染页上都在。核法：裁切原图，不信文本流。

## 5. 口径争点：别把约定当错误

- **P_d vs P_ed**：带按额定 4 kW、齿轮/轴按 P_d 是常见混合口径。先读《参数确认单》§4；若写明“按 P_d 链，不是额定功率”，齿轮/轴不需要按 P_ed 重算，带按 4 kW 反而偏保守。补一句“带按额定、齿轮按工作载荷，电机储备只作启动/过载”即可。只有老师明确要求全按 P_ed，才升级为原则问题。
- **K_A**：齿轮 1.0（表10-2 均匀平稳）、带 1.2（表8-8）、联轴器 1.3（表14-1）是不同部件表，不要求统一。
- **σ_Hlim 锚点**：图10-21c 的定义域有下限（240 HBW）；超出时“沿用锚点、不外推”是既定口径。若该值不控制设计（[σ_H]₂ > [σ_H]₁），影响为零；“不抬高”措辞不准可改成“按 240 锚点”。
- **材料表**：45 调质在表10-1 是 650/360，在表15-1 是 640/355；不是笔误，注明来源即可。
- **表3 两个许用值**：518.4 与 521.1 的差常来自两方案转速不同、K_HN 不同（568.75×0.912≈518.4），不是材料差异。
- **篇幅不对等 ≠ 漏算**：高速轴一节写得长、低速轴三行就完，先看外伸端载荷再判。高速轴外伸端是带轮，压轴力 F_p 与齿轮 F_t 同量级、作用在 90~100 mm 悬臂上 → 支反力不对称、出现负反力、还要用小一号轴承的寿命对照来论证轴颈；低速轴外伸端是联轴器只传转矩（“附加径向力按理想对中忽略”这条前提必须在正文写明），齿轮居中两支承对称，寿命常余两个数量级、尺寸由结构定 → 本来没有可论证的内容。审阅时把“短”当漏算去要求补写，只会逼出一堆重复的例行校核；该问的是那条忽略前提有没有写出来。

## 7. 坑

- 不要用 `pdftotext`（本机不一定有）；优先 `mdkit.py page` + `pdftextlayer`，整页文本用 Swift PDFKit。
- `pdftextlayer` 只打印样本行，别拿它判断整页表格；表格一律渲染 + `region` 裁切。
- `vision_analyze` 整页缩图会编读数；读小字必须裁切，数字与线位以像素/文本为准。
- 不要为了“让它通过”去改本来正确的表；先确认渲染页。
- 不要把外部审计的算术正确当成结论正确：它可能把 P_ed 假设当现行设计、把不同部件表的 K_A 当“不一致”、把跨页表当“缺数据”。

## 8. 落地：改轴系结构的连锁（一处改动五处跟）

审计出的结构问题一旦动手改，`段表` 是唯一真源，下面五处必须同步，缺一处就前后矛盾：

| 顺序 | 文件 | 是否自动 |
|---|---|---|
| 1 | `calc/s3_shaft.py` 的 `段表`（改这里） | 手改 |
| 2 | `calc/s3.json` | 重跑脚本生成 |
| 3 | `figs/fig2.svg`、`fig3.svg` | **自动跟随**（`s5_figs.py` 直接读 `段表`） |
| 4 | 说明书表 8 / 表 9 + 正文“总长 N mm” | **手写，必须手改** |
| 5 | `图纸/calc_输出轴.json` → `输出轴零件图.py` → `.svg` → charter 门禁 | 手改 JSON，图自动重画 |
| 6 | **重出交付件**：说明书 PDF（`build.py`）+ 零件图 PDF（Chromium `--print-to-pdf print.html`） | **必须单独做**，见下 |

四条硬坑：

- **`ls` 一下 PDF 的 mtime 晚于 SVG 再报完成**：生成器只写 `.svg` + `print.html`，PDF 是另一步（Chromium `--print-to-pdf`）。只跑生成器就回「改好了」，用户打开的还是旧 PDF——「你只改了 svg」这类话就是这么来的。重出后渲第 1 页裁一眼改动处（总长、新加的台阶、技术要求编号），别只看 build 的输出字节数。
- **`da min` 是下限不是上限**：轴肩另一头受轴承内圈外径约束（≈d+0.31(D−d)），只按「越大越稳」把肩做大，会顶到保持架；表 6-1 印不出上限，越界值没有表值可引。
- **总长变化的归因写对**：轴肩只换直径时分母一个不动；总长变了必然是某段**段长**变了（如轴端 12→6 缩进闷盖内腔）。报告「295→289」要说清是段长改的，别挂在轴肩上——用户会拿段长逐个相加反推。
- **技术要求加条目排在最后并顺延编号**：按内容位置插会得到「7、9、8」，用户当场截图指出。

- **零件图脚本的段名是字符串切片**：`"ⅠⅡⅢⅣⅤⅥ"[:len(界)-1]` 只到 Ⅵ，加一段就少一个段名，对账 assert 直接报“总长 / 段界末不符”。加段先补到 Ⅶ/Ⅷ。
- **索引型硬编码要跟着数**：基准三角的 `MY − R[4]`、直径标注的 `X[3] + 8.75`、粗糙度引线都按段号写死，插一段之后全部错位——改完必查 `datum_tri` / `dim_dia` / `rough_lead`，别只看门禁红不红（门禁会报 L3-02/G-01，但不会告诉你哪个索引该加一）。
- **窄段上加的 ⊘ 标注容易压在轮廓上**（L3-02），把标注的 y 往段内挪 3~8 mm 即可；门禁全参跑：`check.py <svg> --calc <json> --features <json> --fig-no <图号> --part shaft`。

**省掉重算的判据：先比 跨距 / 悬臂 / 齿轮中心 三个数。** 只在齿轮与轴承之间拆段、只在轴承外侧截短时，这三个数逐位不变，支反力、σ_ca、S、轴承寿命全部保持原值，一个字都不用重算——重跑后直接拿 `s3.json` 对这三个数，对上就跳过全部校核。反过来，一旦动了 Δ1 或轴承位置（如把挡油环从座孔式改成轴上式），跨距变，整条链必须重算。

## 9. 符号代号与教材口径核对（“代号好像跟书上不符”）

交付形态是**一张对照表**：现用 → 教材用 → 含义（页码/式号/表号）。不重出计算过程，本轮一般也不改文件（除非用户点头）。顺序固定：

1. **先取本地现用写法**：`grep -o '\$[^$]*\$' 说明书_part3.md | sort | uniq -c` 一次拿全符号，再 grep 公式库/章知识看库里写的是什么。**报“库里错了”之前必须先看库里到底写的是什么**：库里本来就对、只与“通行写法”不同时，那是教材口径不是 bug，不许提议改库，更不许进“待替换”清单。
2. **教材写法取原文**：`grep -rn "基本额定动载荷" raw/sources/design/chNN-全章OCR.md` 拿原文与页码；例题里的写法同等级算证据（例题写“C=30.5 kN”就定了是 C 不是 C_r；“以小时数表示的…寿命 L_h”就定了 L_10h 应为 L_h，L₁₀ 是 10⁶ 转）。
3. **只报两边确实不同的**，并分三类：真差异（符号体系不同，如 C_r→C、C_0r→C₀、L_10h→L_h、R_1/R_2→F_r1/F_r2）；写法缺失（完整式 P=f_d(XF_r+YF_a)、温度系数 f_t、静强度写成 C₀≥S₀P₀ 而不是只写比值）；**未核**（下条）。

**教材各处符号口径（被问“这是书上的写法吗”先查这张表，别凭通行写法答）**：

| 位置 | 教材写法 | 常见别名 | 证据 |
|---|---|---|---|
| 基本额定动载荷 | **C**（原文括注“C_r 或 C_a”） | C_r 是分类型写法，不等于错 | ch13 OCR，p.322 起 |
| 基本额定静载荷 | **C₀**（原文“径向基本额定静载荷，用 C_0r 表示”） | C_0r | ch13 OCR |
| 小时寿命 | **L_h**（L₁₀ 是 10⁶ 转，不可带 h） | L_10h | 式13-5 |
| 载荷系数 | **f_d**（表13-6 表头下标是 d；扫描件 5–6 px，别判成 p） | f_p 是通行写法，书上不用 | p.337 |
| 轴承径向载荷 | **F_r1、F_r2**（两个支承合成后） | R_1、R_2 | p.338 |
| 支反力分量 | 水平 **F_NH**、竖直 **F_NV**，下标带支承号（F_NH1、F_NV1…） | R_1H/R_1V：课设指南书的通行写法，数值等价、不算错 | 图15-24，p.387；例15-1 表格 |
