# 程序化出图管线（参数 → SVG → 校验 → PDF/PNG）

## 何时用
零件图要按毫米精确画、且会反复改参数（换模数/齿数/结构形式）时。手改坐标的重画成本随参数变化爆炸，必须做到「改一处参数、重跑一条命令、图自动正确」。

## 一、参数 schema 四块，一次列全
写渲染之前把 schema 定死，别边写边加：

```
geometry     m, z, alpha, x, d, d_a, d_f, b, structure, bore_d,
             keyway{width,t2,length}, hub{}, web{}, chamfer, fillet
annotation   dims{每项 tol/tol_upper/tol_lower/reference/datum}, roughness{部位→Ra}, gdt[{symbol,value,datum}]
tables       grade, param_table[{name,sym,from,fmt}], title_block{}, tech_req[]
sheet        size, scale, views{}, margins, line_widths{}, hatch{}, fonts{}, layout{锚点}
```

**坐标规矩**：所有点 = 版面锚点 + 零件尺寸 × s；代码里每处算式后面注释 `# 算：…`。整份文件只允许 `sheet.layout` 里的六七个锚点（主视图左端面、端面图圆心、参数表、标题栏、技术要求、投影法符号）是写死的图纸版式，其余一个都不许。

端面图圆心这类锚点写成「锚点下限 + 依视图尺寸自动外推」：`lcx = max(anchors.left_cx, x1 + 10 + r_a)`，大齿轮才不会被主视图压住。

## 二、三段式
`render(params) -> svg 字符串`；`check(svg, params) -> 问题清单`，每条写成 `[项号 项名] 实测值 vs 期望值（或算式）`——报告要能直接指出哪条、错多少，不能只说“有问题”。

check 六项照用户的验收单：① 第一角画法（视图方位、高平齐、投影符号）② 三线画法（齿顶/分度/齿根线宽线型、剖面线规则）③ 尺寸完整/不重复/不封闭/箭头规范/**尺寸界线越过尺寸线 ≥ 2 mm**（每条尺寸线数穿过的细线，不足 2 条就报：箭头悬空、界线没碰到尺寸线） ④ 参数表+标题栏+技术要求齐全且与参数一致（参数表上边线/右边线须与内框坐标相等 ±0.1 mm、表内不得出现“参数表”字样；标题栏逐格文字与输入参数比对） ⑤ 粗糙度/公差位置规范 ⑥ 所有标注数值与输入参数逐项比对 ⑦ **开放折线不得闭合**（弧类元素必须是 `polyline`，发成 `polygon` 会在两端点间多一条水平弦：齿区里不许出现横贯轮缘的线段）⑧ **文字不压格线/不越格**（标题栏与参数表内每段文字与格线求交，格线含外框 `rect` 四条边）；⑨ **字体合格**（`<style>` 里不得出现 PingFang/Heiti/sans-serif）；⑩ **图形不侵入标题栏**（任一元 bbox 与标题栏矩形相交且中心不在其中 → 报错；图框 rect 与标题栏自身图元排除，否则永远报两条）。

## 三、校验必须三层，“全绿”单独没有意义
1. `check` 0 问题。
2. **反向测试**：往 SVG 里逐个注入典型错误，要求对应项号报错——改齿根圆半径、齿顶圆改细线、剖面线间距打乱/挪进齿区、删箭头、尺寸线挪进图形、尺寸重复、尺寸链封闭、表值改错、粗糙度值改错、形位公差值改错、引线脱离表面、基准字母改错、参数自相矛盾。20 项上下，全中才算 check 有约束力。
   注入用工具函数按 id 改属性（`tag_of` / `set_attr` / `set_text` / `drop` + 正则），**不要写死整串 `<circle stroke-width="0.5" .../>` 去 replace**：生成器的属性顺序不固定，必然匹配不上。改动 `y1` 这类端点时要连 `y2` 一起平移，否则 45° 线变成非 45°，报的是“角度”不是想测的“间距”。
   **每加一条新检查就当场配一条注入**（删孔口竖线、把尺寸线平移 3 mm 让界线不穿过、参数表下移 2 mm、插一行表名、把中心线拉到标题栏里），否则新检查等于没写；反过来，反向测试报“未捕获”时先怀疑注入没生效（属性名/id 写错），不是检查失灵。
   **换题时最容易集体失灵的正是“字符串目标”**：注入用 `drop_text(f"φ{P['da']:.3f} h11")`，而新题的自检把分辨率改成 `:g`（`φ140`），注入目标串根本不存在，同一轮四条反向测试一起报未捕获（尺寸、参数表、越界、压字）。规矩：**期望字符串与注入目标都从 P 现场格式化，共用同一个表达式**（抽成 `DIMS = {...}` 常量，check 与反向测试都引用它），不要一处写死 `"φ140 h11"`、一处写 `:.3f`。
3. **扫像素**：PDF→PNG 后按 mm 取样，比对两类量：
   - 线位：齿顶/分度/齿根/孔壁/轴线/端面/三圆/键槽壁/键槽顶边，偏差 ≤0.5 mm；
   - 墨量：剖切区 ≈ 线宽÷间距（0.18/2.6 ≈ 6.9%）、齿区 = 0、孔内 = 0、图框外 = 0。
   取样三个坑：探测列不能压在中心线上（点画线的 dash 给出“有线”的假读数）；墨量带要避开线本身 ±0.4 mm（否则边界线被算成“该处有墨”）；窄区取在槽内、偏离中心线 0.6×半宽处。**“应为空”的探针（齿区、孔腔、键槽外的轴孔）边距必须大于粗线半宽加抗锯齿：粗线 0.7 mm → 至少 0.8 mm**，用 0.45 会直接读到齿根线本身。**直线度类探针的取样区间也不要顶到相邻线**（腹板面在 76.8/83.2，墨量框就取 77.4~82.6，否则同样读到线）。
   再加两条：**探针口径先对几何，再对图**——取样区间按真实要素定（轮毂端面只存在于轴孔→轮毂外圆之间，不是整段轮毂长），文字唯一性排除参数表/标题栏区域，内框越界排除图框自身；**两条线粘成一条时先做像素剖面**——1:2.5 下 0.37 mm 的弧间距小于笔画宽，栅格化后视觉上就是一条粗线，沿 x 取一条竖直灰阶剖面看黑带是 0.15 mm 还是 0.5 mm，再决定重画还是本来如此。

## 三½、几何检查自己的坑
写 check 时这几处每次都会把图误报成错，先排除再改图：
- **`tag.endswith("line")` 会连 `<polyline>` 一起选中**，取 `x1` 得 None 直接报 TypeError。判标签用 `e.tag.split("}")[-1] == "line"`，`text`/`rect` 同理。
- **emit 出去的坐标已经是 SVG（y 向下），做几何检查时不要再 `210 − y`**；再翻一次会让所有线段落到纸面下部，表现为“全线越界”或“字压格线”。
- **矩形/框类参数的顺序是 `(x0, x1, y0, y1)`**：调用端按 bbox 顺序 `(x0, y0, x1, y1)` 传，相交判定会变成无意义值，报警真假难辨（症状：水平线被报成穿过上方 10 mm 处的文字）。写完先拿一条已知不相交的线对一次。
- **文字压格线的格线集合要包含 `rect` 四条边**，只统计 `<line>` 查不出“字压边框”；反向测试要注入一条“把单位栏文字压到底框线上”，否则这条检查等于没写。
- **“不侵入标题栏”类检查要排除图框与标题栏自身的矩形**，并且判定用“中心点不在框内 + 包围盒相交”，只用相交会把图框 `rect` 自己报成侵入。
- **剖面线识别会吃掉 45° 尺寸引线**：候选条件（`thin` + 角度落在 45°±2° 或 135°±2° + 长度 0.6~14 mm）挡不住引线，一改孔径/槽深让引线斜率变到 47°，自检就报“角度族 [45, 133] ≠ [45]”和“剖面线越出齿宽”，其实是图没错。规矩：**所有引线/符号线生成时带 id 前缀**（`ra_` 粗糙度、`hub_` 槽深、`dim_`/`lead_` 其余引线），剖面线候选里按前缀元组排除；剖面线本身不带 id，按前缀排除是安全的。只靠“在不在零件 bbox 里”是挡不住的。

## 字体落地（中文图纸最容易静默错的一环）
macOS 的华文仿宋是 **AssetsV2 里的按需字体**：`family:'STFangsong'` 和 `family:'华文仿宋'` 在 Chrome 里都解析不到，静默 fallback 到 `serif`→ STSongti，图上就是宋体（缩略图里几乎看不出区别）。可靠做法：
1. `cp "/System/Library/AssetsV2/.../STFANGSO.ttf" <项目>/fonts/`，字体跟图走，不动系统。
2. SVG 的 `<style>` 里 `@font-face{font-family:'GBFang';src:url('fonts/STFANGSO.ttf') format('truetype')}`，`.txt{font-family:'GBFang','STFangsong',serif}`（单独打开 SVG 时相对路径有效）。
3. 打印页**必须把 SVG 内联进 HTML**（读文本、切掉 `<?xml?>`、从 `<svg` 开始插入），再在文档级写一次 `svg text{font-family:'GBFang','STFangsong',serif}`。`<img src=x.svg>` 加载的 SVG 不允许取外部资源，字体照样 fallback。
4. 验收：看渲染图字形（仿宋横竖粗细接近、带楷书笔意），或在 PDF 里搜 `STSongti`/`STHeiti`——还能搜到就是没生效。

## 四、自证式校验是坑
参数表/技术要求里的数值**不许在 tables 里另存一份**——check 拿表对表永远通过。表行只存 `{"name":"模数","sym":"m","from":"geometry.m","fmt":"n"}`，渲染时按路径现场解析（`_resolve(p, "geometry.m")`），check 再拿渲染出来的文字与参数逐格比。技术要求里的圆角/倒角/精度等级同理写成 `{fillet}` / `{chamfer}` / `{grade}` 占位符再代入。

## 五、SVG → PDF/PNG 的落地细节
- **剖面线不要用 `<pattern>`**：Chrome 打印 PDF 时 pattern 不落地（同一文档里实心填充正常），出图后整块剖切区是白的。改为按 spacing 逐条生成 45° 线段，取 `c = x + y` 的**全局等距网格**（`c = k·spacing·√2`），多块剖切区相位才一致、check 能量间距；`clipPath` 只作兜底，不用它当裁切机制。
- **转 PDF**：HTML 包一层再打印，否则 Chrome 给 Letter 竖放——
  `@page{size:297mm 210mm;margin:0}` + `img{width:297mm;height:210mm}`，`chrome --headless=new --no-pdf-header-footer --print-to-pdf=out.pdf wrap.html`。
  本机**没有 Chrome**，`chrome` 那条命令换成 Playwright 自带的：
  `~/Library/Caches/ms-playwright/chromium-1234/chrome-mac-arm64/"Google Chrome for Testing.app"/Contents/MacOS/"Google Chrome for Testing" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf=<out>.pdf --allow-file-access-from-files _print.html`（旧版 `--headless=new` 不认）。
  出完核 MediaBox：841.9×595.0 pt = 297×210 mm，页数 1。
- **只想快速看一眼 SVG（不打印）**：`qlmanage -t -s 1600 -o <dir> fig.svg` 直接出 `<dir>/fig.svg.png`，零依赖，不用 Chrome / Playwright。两个坑：① 输出是**正方形画布**（1600×1600），内容按宽度缩放后**靠上**放，不是居中——拿「px = mm × (W/图幅宽) + 居中留白」去算裁图坐标会整片偏，裁到的“台阶”其实是力学模型；② 映射必须从图象自身量：`np.where(np.array(im.convert("L"))<128)` 拿暗行/暗列，认出轴线那一行、图框那两条边，再反算 px/mm 与偏移。
- **别用眼睛数线，先量再改**：同一张图先在整页缩略上判“上轮廓缺一段”、又在 4× 裁图上判“台阶竖线穿进轴内”，两次都是错的——把 `<polygon points=…>` 逐点打印出来（x、y、相对轴线的 dy）才看到轮廓是闭的、台阶是短竖边。裁图坐标没校准前，视觉结论一律不能拿去改代码。
- **只判一类元素就只渲那一类**：把 SVG 里除了目标元素以外的项全删（`re.sub` 只留 `<polygon class="thick">` 加回 `<style>`），渲成一张只有轮廓的图，闭不闭合、台阶在不在、对称不对称一眼就看得出。混在整张图里时，尺寸界线、剖切线、文字基线都会被误看成轮廓。
- **vision 复核**：裁块 500~1100 px（整页大图必超时），只用来找压字/重叠/缺行；它会把自己裁断的内容说成“图纸被截切”，也会编读数，几何一律以像素扫描为准。

## 附：标注布局（同心圆件挤不开时）
端视图外圈到图框之间留一条 ~50 mm 宽的“右栏”，形位公差框与孔组排在那里，引线不往视图内部穿。**直径不要排在这一栏**：从圆周拉一条水平线到右栏写字，既不过圆心也没有可辨箭头，属不合规标法；同轴多个直径改到主视图左侧做嵌套竖直尺寸（内小外大，见 `gb-gear-drawing.md`「标注通则」），端视图只留基准框与孔组引线。
- **角度由目标高度反算**：文字标签定在 `y_lab`，源点角度取 `θ = asin((y_lab − SY)/r)`，引线走到该半径时正好水平；再径向外推到 `1.1r`，然后水平到固定 `x_col`，文字接在后面。几组标注的 `y` 拉开 9~12 mm 就不会互穿；反过来先选角度再定文字位置，必然交叉。
- **窄槽用外置箭头**：6 mm 宽的槽（`16 JS9`）内部插不下箭头，尺寸线两端延长到槽外、箭头从外向内指，文字标在延长线端部。
- **带公差的深度用 45° 引线**：主值 + 上偏差 + 下偏差三行叠排，上偏差在上、下偏差在下，行距 ≥2.5 mm 才不叠字（按字号 2.0 的 bbox 算，1.2 mm 行距会糊成一坨）。
- **两个圆跳动分开引**：端面圆跳动引到端面环带（φ250~φ302.4 之间）、齿顶圆径向引到外圆，源点角度错开 25° 以上，公差框上下排。
- 配合直径写 `φ250 H7/r6`（同一尺寸里孔轴公差带并列），基准字母挂在该尺寸线上，别另拉一根引线到孔壁。

## 六、出图顺序（build.sh 一条命令）
1. render + check（非 0 退出就停）
2. 打 PDF（HTML 包 @page）
3. PDF 逐页转 PNG
4. 扫像素复核
任何一步失败都不许进下一步；四步全过再给人看。

### 换题改图时，像素脚本必须 `import gear_draw` 取几何
把 `MX/MY/SX/X_L/R_TIP/R_BORE/KW/Y_KEY` 再手抄一份到 `verify_pixels.py`，换题必炸：一次换题后 27 项里 20 项假报，全是拿上一题的半径去量新图。正确做法是 `import gear_draw as G` 直接引用模块常量（脚本本身无副作用），取样框跟着导出量算（`X_L+1 ~ X_R-1`、`Y_BORE+1 ~ Y_ROOT-1`），只留阈值和判定条件。

### 像素判不了的结构，改用 SVG 结构判
半径小的孔（φ26 在 1:2 下 r=6.5）开键槽后，缺弧只有 2×asin(KW/r)≈36°，“孔在槽口处断开”用像素永远判不准：槽侧线、穿过孔心的轴线都在 ±0.5 mm 容差里，实测着墨 44%~52%，改成任何阈值都会假报或漏报。直接把 `side_bore` 折线的点集取出来算角度：最大角隙应 ≈36° 且其平分角落在 270°±8°。像素只负责线位与墨量，拓扑（断开、开口、封闭）交给 SVG。
