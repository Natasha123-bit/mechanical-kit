# 做题与取值的 33 条陷阱 · 出图/标注/版式/校验

> 自 `mechanical-homework/SKILL.md` 的「陷阱」一节按下沉（2026-10-26），共 19 条，**正文逐字未改**；原节其余 12 条在另一份。

- **`$` 残留**：手拼 HTML 模板写成 `${m('...')}$` 会在成品里留字面 `$`。现在 `md2html.py` 生成后断言 `$` 为 0（违反即退出），走 `mdkit.py book` 不用再手工 grep；手写 HTML 的场合仍要 `grep -c '\$' 输出.html`。
- **分页**：标题会与后面的公式/表格分家。`book.css` 已内置 `.cap{break-after:avoid}`、`.fm{break-inside:avoid}`；手写 HTML 时自己记得加。
- **别用生图模型画零件图**：image2.5 之类生成不了逐字准确的尺寸、公差和汉字，出来不能用；用户提议时回一句原因，继续用 SVG 按毫米画。
- **不要为画零件图引入 SVG 库（svgwrite 等）**。图元层本来就只是 `line/circle/rect/text/path` 加几个 mm 坐标的小函数（`L/C/RECT/T/arrow/dim_h/rough/tol_frame/datum`）；库只省字符串拼接，省不了文字基线、旋转公差叠排、窄处让位、中文字宽这些真正费时的地方，还多一层坐标/单位语义（自写则 1 用户单位=1 mm，`viewBox="0 0 297 210"` 直接对应图纸）。要复用的是**图元函数本身**，不是库；抽成 `mdkit/draw/gbdraw.py` 比换库有价值（已建：`Sheet/L/CIRCLE/RECT/T/ARC/ARROW/DIM_H/DIM_V/LEAD/ROUGH/TOL_FRAME/DATUM/HATCH`）。用户问“要不要用 svgwrite”时，把这个理由讲清楚再推荐把现成图元抽出来。
- **剖面线别用 SVG `<pattern>`**：Chrome 打印 PDF 时 pattern 不落地，剖切区整块发白（同一文档里实心填充正常，所以容易误判成 CSS 问题）。按 spacing 逐条生成 45° 线段、取 `c=x+y` 全局等距网格，PDF/PNG 都能看见，也才好量间距。
- **`gbdraw` 里给元素写 `fill` 不生效，只有 `poly` 的 `fill="solid"`（纯黑）能实心**：`Sheet.svg()` 为每种线型生成 `.thin{…;fill:none}` 这类 CSS，CSS 规则优先于元素的 `fill` 属性（presentation attribute 优先级最低），所以 `<path fill="#ccc">` 出来仍是空的。要浅色/斜纹填充就自己按 spacing 画细线（弯矩图的竖向细线、剖面线的 45° 线都这么来）；真要实心只能是黑。别用「打开 SVG 看有 fill 属性」当证据，渲成 PNG 看那块有没有墨。
- **弧和折线一律发 `<polyline>`，不许发 `<polygon>`**：polygon 隐式闭合，会用一条弦把弧的两个端点连起来——齿顶/齿根/分度三条弧各多出一条横贯轮缘的粗线，缩略图上就是"凭空多出一条横线"，而线型/尺寸/表格类 check 全绿（弦的颜色、线宽都合法）。只有箭头这类实心件（`fill="solid"`）才发 polygon。辨认方法：多出的线恰好等于该弧两端点的高度（对称弧两端等高，所以弦是水平的）。
- **PDF 版面「看起来错了」先量再改**：1189 px 的整页缩图会把满宽图表看成「双栏并排」「表格挤成竖排」「公式显示成 TeX 源码」，照着改连改三版都改不掉。判据顺序：① 解析生成物（`grep` HTML 里那段结构，看 `.fm`/`<table>` 在不在）→ ② 像素量（PIL 扫每页墨迹 x 范围，全部落在 25/188 mm 版心内即正常）→ ③ 浏览器按打印宽度量（A4 25/22 mm 版心 = **616 px 视口**，`el.scrollWidth > el.clientWidth` 才是真溢出，表 `width:100%` 恒等宽，看得窄是缩图的错觉）→ ④ 最后才是 vision，且只裁区域看。同一张页面图读两遍结论相反时，直接去量，不要再换个角度读第三遍。
- **check 报警先核校验口径，别急着改图**：先问"是图错了，还是探针的期望值错了"。四类假警报都出在校验端——① 尺寸文字"唯一性"把参数表/标题栏里的同形数字（"50"）算成重复，按区域排除；② "不得越出内框"把图框矩形自己算进去，按 id 排除；③ 线位探针取样区间比真实要素长（轮毂端面只从轴孔到轮毂外圆 7 mm，不是整段 18 mm）；④ 坐标二次翻转（emit 已把 y 翻成 SVG 向下，bbox 又翻一次，全线误报越界）。判据：到图上量一遍像素，图上对就改探针。
- **参数表数值不许另存一份**：tables 里再写一遍 "2.5"，check 拿表对表就永远通过。表行存 `from="geometry.m"` 现场解析，技术要求同理用 `{fillet}`/`{chamfer}`/`{grade}` 占位符。
- **“0 处问题”不是验收依据**：自检函数必须做反向测试——注入 20 项典型错误（改半径/线宽/表值/公差、删箭头、尺寸重复或封闭、引线移开表面）看它逐项报不报。改属性的测试工具按 id+正则写，别拿写死的整串去 replace，生成器属性顺序不固定。
- **用户说“轮齿类零件的全剖视图少了很多线”时照教材图例逐条勾，别猜**：完整清单在 `references/gb-gear-drawing.md`「常见出错点」——齿部三线（不剖）、端面竖线通高、配合面、轮缘/腹板/轮毂各面、**键槽台阶**、**剖到的孔腔**（分布角要让 90°/270° 落在剖切面上）、**轴孔口两条竖线**；对照图 8-52（线型）与 8-53（零件图）。
- **新写一个出图模块时，先把画法口径写成断言再画，别先画再数元素**：数顶点、数元素、数字齐全这类测试能全绿而图仍是废图——实测同一张草图同时漏了台阶面不贯穿、直径只有漂浮文字没有尺寸线、件号只有箭头没有引杆三条，测试 29 项全过。合格的自检是「每条口径一个能失败的断言，断言里出现坐标/端点/2 mm 这类量」，不是「元素计数」。开工顺序：把已验收的图（`图纸/*.py`，如 `输出轴零件图.py`）里的画法逐条抄成口径清单 → 清单进模块 docstring 并注明出处（文件:行号 / 用户口述）→ 每条写成断言 → 再出图。口径清单也只写一份，散在聊天里下次必漏。
- **口径闸要量生成物，不是量脚本**：`scripts/verify_drawing_conventions.py 图.svg`（本 skill 自带）八条硬判据——仿宋且 STFangsong 在前 / 线宽只有 0.25·0.5 两档 / 箭头 1.0~3.6 mm / 每条尺寸线两端界线越 1.9 mm / 水平数字在线上方 0.6~3.0 / 竖直尺寸线 ≥4 mm 贯穿 / 竖直数字在尺寸线左侧 / φ 值不落在尺寸线中点；非零退出可直接当提交闸。写新判据时注意：**尺寸线要先按「两端都有箭头尖」识别**，只按「长细线」找会把引线尾、参数表横线当尺寸线，误报一大片；**「避开中点」只对 φ 生效**，62.5／74.9 这类长度深度尺寸的数字本来就该在尺寸线中段；gbdraw 输出时 y 已翻成 `H − y_sheet`，判据里别再翻第二次。
- **审「脚本是否和之前几张图对齐」先分世代**：老一代 svgwrite 件（字体 `GBFang` 优先、线宽 0.2/0.25/0.5 三档、字号档 2.0~5.04、箭头 0.83~3.05）只能当版面参考，**不能当入库基准**；同代 gbdraw 脚本之间字体、线宽、字号档、箭头尺寸、标题栏代码应当逐字相同。对账方法就是拿口径闸把每张图量一遍，再把差异当 bug 修——不要凭读代码判断「应该一致」。
- **Chrome CLI 打 A3 PDF 会退回 Letter**：`chrome --headless --print-to-pdf 图.svg` 出的是 612×792 pt。包一层 HTML 写 `@page{size:420mm 297mm;margin:0}` + `img{width:420mm;height:297mm}` 再打印，打完回读 `strings 图.pdf | grep MediaBox` 确认（A3 = 1191.12×841.92 pt，A4 = 841.89×595.28 pt）；PDF 尺寸错了整张图的「毫米」就全作废。
- **尺寸标注固定查五件事**：① 尺寸界线离轮廓 0.5 起、**越过尺寸线 2 mm**（`dim_v` 的符号易写反，症状是箭头悬空）——**越出方向按「远离零件」的那一侧加 2 mm**：链条画在零件下方（图纸 y 向上）时是 `yl − 2`，写成 `yl + 2` 会停在尺寸线前 2 mm，缩略图上看像连着、量出来是 2.00 mm 空隙；但**尺寸线自己画到箭头尖端为止，不许越出轮廓**（界线才越过；直径的界线就是轮廓本身）；② 直径尺寸线**贯穿整个直径**（不是只画到半径）、两端箭头朝外、φ 值竖排在尺寸线**左侧**，同轴多直径右侧**内小外大嵌套**，别用水平悬空引线代替；③ **数字位置**：水平尺寸写在尺寸线**上方**，竖直尺寸写在尺寸线**左侧**（两者都容易写反成线下方/线右侧）；④ 参数表**不写表名**、上边线与右边线贴内图框；⑤ 标题栏 **GB 简化式、全封闭网格**：上区名称/材料/比例/图号（图号标签单独一格）、制图行 `制图|姓名|日期|数量|值|共几页`、审核行 `审核|审核人|日期|单位`，一律居中，名称格底边那条 y=24.5 横线必须通长。分格细则见 `references/gb-gear-drawing.md`「标注通则」「标题栏」。
- **标题栏/参数表的字要程序化验“不压格线”**：文字 bbox 与格线（含外框 rect 四边）做线段相交；格内居中**基线 = 格中心 − 0.24h**（bbox 上 0.78h、下 0.3h），写成 +0.24h 会整体偏高；标题栏矩形内不许有任何图形线（端视图竖直中心线最容易伸进来）。
- **按「p.×× 图×× 」/「p.×× 表××」抄版式时：先在图题处定位、再放大逐要素清点**。扫描页一页常排两三张图，图题在图下方，整页缩略图上看不出哪张是哪张——照缩略图去画，会漏掉整类要素（轴零件图的竖直径向尺寸线、表19-1 的中间图栏与右侧 1/5 结果栏）。做法：`ocrbox 页图.png | grep 图20-6` 拿 caption 坐标 → 按坐标裁到 ≥1500 px 宽 → 列出要素清单（尺寸线怎么画、分几栏、栏宽比例、图放哪栏、剖面怎么开）→ 与自己的图逐条对表 → 再动笔。用户说「格式按 ×× 表××」= 版式要素逐条对上，不是「有张表就算对」。逐项清单见 `references/reducer-design.md` 第五节。
