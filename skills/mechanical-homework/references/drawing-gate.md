# 交付自检闸（drawing gate）的设计口径

适用：写或改 `核查*.py` / `verify_*.py` / `charter/*.py` 这类交付前的自动闸；或者听到「图错了但你的校验全绿」。

一句话：**闸的价值在于期望值独立于生成器**。同源自证的闸只能证明「我按自己的错继续错」——它每次都会给出漂亮的通过报告，而图仍然是废图。

用户甩一份成文规范（经验总结 / 自检规程 / 画法手册）说「把它做成规程」时，**不要只改自己踩过的那几条**——那等于把一份规范当 bug 清单用，下一条没踩过的照样漏。做法：全文逐节抽成条款（一条一个可判定命题，带 id），每条标三态 A（有自动检查）/ M（靠人签）/ X（已规定但无实现），再拿 `rules.json` 生成正文、拿反射生成接口表——**覆盖率（A/总数）当事实报，不当目标报**；X 没清零之前，交付只能写“人工核对 + 未自动检查”。

## 五条硬约定

### 1. 期望值必须独立来源，闸里禁止字面量

三个可接受来源：计算书 `calc/*.json`（尺寸链与轴段表）、参考件 SVG 源码（标题栏格线、符号尺寸、缺口朝向）、标准表（GB/T 1095 键槽、公差档）。

反例（真实踩过）：
- 生成器与闸都 `import model`，闸拿 model 的值当“标准”——model 错就一路错。
- 上一版把别的题的图号抄进图面，闸的字段白名单里也写着同一个错图号，于是「串题」这条永久通过。
- 闸把段长写成 `["394.05", "79.9", ...]` 字面量，改设计后只在两处同时改才不报警——这种闸的作用是防止自己改，不是防止图错。

判据：**闸里每个期望值都要能指出出处行**（哪个 json 字段 / 参考件第几行 / 标准表哪一格）。指不出来就是猜测，删掉或降级为「未检查」。

### 2. 元数据契约：缺 `data-feature` 算不通过，不算跳过

生成器给每个图元写 `data-role`（outline / centerline / hatch / dimension / extension / arrow / datum / tolerance-frame / roughness / title-grid / section-outline）+ `data-feature`（特征 id，如 `seg3_shoulder`、`keyA_width`）+ `data-src`（模型字段路径）。

闸的第一条规则就是验契约：任何图元缺 `data-role` 或缺 `data-feature` → **不通过**，不是「跳过」。

反例：`key-outline` 40 个元素 `data-name` 全是 null，而检查规则写的是 `e["name"] == k["name"]` —— 筛选恒空，规则每次报「A—A 无键槽母线」，把对的图判错，误差还伪装成“发现问题”。**生成器先过契约检查，才准出图。**

分组只能给**默认**角色，不得覆盖子元素自己的：`G("dimension", 尺寸线, 箭头, 数字)` 若把三个子元素一律标成 `dimension`，箭头与数字就失去身份，“按角色找箭头 / 找数字”的规则全在数错东西。按元素类型分派（`G_SUB`：`line→dimension`、`polygon→arrow`、`text→dimension`），子元素自带 role 优先。同理 `data-view` 的默认值要取分组自己的 view，**不能拿 role 当 view 的默认值**——写错过一次，所有分组子元素的 `data-view` 全成了 `"dimension"`、`"title-grid"` 这类角色名。

name 可由分组继承（一个断面的所有图元都属于 `B—B`），否则剖面线、键槽轮廓这些成组元素整组缺名，选题归类的规则一律空转。

**调用点要短到能坚持打标。** 几十处 `ROLE("outline", None, elem, feature=…, view=…)` 抄到第三遍就会有人偷懒，最后只有新写的代码带身份、旧块全是空的。给常用角色各封一个单行的快捷函数（`out(e, feat)` / `ext(e)` / `dim(e)` / `arr(e)` / `lead(e)` / `txt(e)`），把 role、view 和 feature 的写法收进去，调用点只剩 `add(out(L(...), "seg3.od+"))`。改造旧图的顺序固定：先修库里的分组/继承语义 → 再加快捷函数 → 按块（主视图轮廓 → 标注 → 表格 → 技术要求）逐块补 → 每块跑一次 `check_contract.py`。补完图元数会明显变小（几百条碎线合成一条 path，890 → 406 这种），**元素数变少不是回归**。

### 3. 几何检查，不是元素计数

| 想验的事 | 计数写法（错） | 几何写法（对） |
|---|---|---|
| 轴肩圆角 | `<path>` 个数 = 轴肩数×2 | 从 `d` 取端点与前两点：起点切线与母线平行、终点切线与轴肩平行、端点落在断开的母线上 |
| 尺寸标注 | 文字串在不在 | 五要素分别验：起止要素、界线起止（是否越过尺寸线 2 mm）、尺寸线、箭头尖落点、文字与模型值 |
| 剖面线 | 每条线取 5 个采样点 | 按**图上的** `section-outline` 路径做点在多边形（0.05 mm 步长），缺口矩形内采样数 = 0 |
| 键槽开口 | 有没有「闭合弧」 | 两条母线右端 x 是否落在端面线 x 上（±0.15） |
| 剖切符号 | 字母集合相等 | 每个字母两条短画 + 箭头成对、位置穿过对应键槽、箭头朝观察方向 |

计数对**方向、切线、起止点、归属**天然无感——这几样恰好是零件图最常被退回的地方。

### 3½、配对判据：按几何配，别按 name 分（写 L1 十条结构规则踩出来的）

**name 覆盖率不是 100%，任何按 name 分组的规则都会静默落空。** 实测样例图 role 411/411、name 107/411（26%），19 条尺寸线全部无 name：`groups_by_name("dimension")` 返回空，规则报「图上没有 dimension 组」而不是「不通过」——看着像这图没有这类元素，实际是判据配不上。写规则前先量一遍 `(tag, data-role)` 与 name 覆盖率；不满格就一律用坐标配对：箭头尖距线端 ≤1.5 mm、文字距线中点 ≤8 mm、界线与尺寸线求交。name 只留给确实成组的东西（断面 A—A、特征 id）。

**尺寸读数取这条尺寸线上的箭头尖间距。** 三层错法都踩过：
- 取线长 → 尺寸线被台阶断成两段（140→167.5、167.5→178），`2.5±0.1` 读成 27.5；
- 取全图最近的值 → 图上有 φ40 段，把 41 改成 40 也能凑上一个合法读数，注入直接漏抓；
- 取该线上的箭头尖 → 正确。

**但「这条线上的箭头」不等于「同一行所有段合并后的箭头」。** 一行上首尾相接的 41/68/10/11/85 是**五个独立尺寸共用一条线**，整行合并成一个组后删掉一个箭头、组里还剩 5 个，判「通过」——删箭头的注入就是这么漏的。按接缝分流：**接缝处有箭头 → 是两个尺寸，不合并；接缝处没箭头 → 是同一条尺寸线断成两段画（2.5 那条），合并**。合并后还要「至少两个**不同位置**的箭头」（间距 ≥0.5 mm）：接缝处两个尺寸的箭头常落在同一个 x（41 的右箭头和 68 的左箭头都在 106），只数个数会把缺箭头判成合格。

**一条尺寸界线可以服务多条尺寸线。** 41 与总长 297 共用 `x=65` 那条界线（y 97.2→26），逐条尺寸线判「越界 1.5~4.5 mm」会把共用界线报成超标 21 mm。正确算法：起端取离轮廓近的端点，找与该界线相交的所有垂直尺寸线，取**最外侧**那条，越界量 = 起端到外端全长 − 最外交点距离。

**φ 用引出线注写是合规画法**，不能要求两端箭头：从轮廓引一条斜线出头、写「φ52 +0.1/0」，箭头只指一处圆周。φ 的判据改成「存在 leader，一端落轮廓 ≤6 mm 且另一端距文字 ≤30 mm」。

**旧图把文字一律记 `role="label"`、身份写在 `data-name` 前缀里**（`dimension 41`、`upper deviation`、`section name A—A`）。在内存副本上按前缀归一成语义角色，别改已验收的交付物文件；但也别为了让 L0 转绿把 `label` 登记进白名单——那是把契约放宽到谁都能自造角色，根治是改生成器打标。

**断段/缺箭头的尺寸线要报「未核」而不是悄悄跳过**：L1-01 已经把缺箭头报出来了，L1-02 的 evidence 里要写「N 条缺箭头或文字未核（见 L1-01）」，不能拿剩下的条数冒充全覆盖。

**比例从标题栏读，别写死 1:1**：齿轮类零件图常是 A4 横放 1:2，图面量 70 mm 对应真值 140 mm，硬按 1:1 读会把 `φ140`、齿宽 `65` 全部判错。尺寸读数换算 `真值 = 图面长度 × n`；但界线越界的 1.5~4.5 mm、箭头长宽这些是**图面**量，不换算。

**断面名只认 `hatch` / `key-outline` 的 `data-name`**：补身份之后 `section-outline` 会被编成 `SEC.1…SEC.6`，拿它当断面名集合会把 `A—A` 判成「没有对应断面」。

### 3¾、身份补齐：旧图零 role 时先补身份，别先改判据

`charter/identify.py` 补身份（不在闸里，是闸的前置）。三种缺身份各有对应做法：

| 症状 | 做法 |
|---|---|
| role 是自造别名（`label` / `zone-range` / `zone-boundary`） | 按 `data-name` 前缀映射回登记角色（`dimension 41`→dimension、`upper deviation`→dimension、`common datum`→datum、`section name`→view-label）；前缀也没有就按内容判：单大写字母 = 剖切字母 → `view-label`，整句（带标点或 >12 字）→ `text` |
| role 对、name 空（尺寸线 19、箭头 55、界线 23） | 按 role 分组、`(y,x)` 排序编号 `dim.1 / arr.1 …`；`MULTI_OK` 的角色不编号——C5 本来就不问它们要名字，硬编号只会把覆盖率的数字冲好看 |
| 零 role（整张图一个身份都没有） | 四层推：id 前缀（`tip_`/`root_`/`dimline_`/`ra_`）→ 元素类型 → 线型 class（thick/center/dim/sym）→ 版面分区（参数表 / 标题栏 / 主视图 / 端面图，按坐标切）。45° 斜线判剖面线，因为轴线、界线、尺寸线全是横平竖直，斜的只剩它和引出线 |

文字判分区时 `text` 的包围盒要按 `(x, y, x, y)` 返回——漏了这条，所有文字都落在原点分区里，「标题栏内容」被当成尺寸数字。

**只改 data-\* 属性，几何与样式一字不动，改完必须像素回归。** ElementTree 重写会让 diff 涨到几百行（属性重排），那不代表图变了：headless Chrome 截图前后各一张，`ImageChops.difference(a, b).getbbox()` 返回 `None` 才算安全。

**Chrome 截图窗口尺寸按 SVG 的 mm 尺寸换算**：`width="420mm"` 在 96 dpi 下是 1587 px，`--window-size=420,297` 只截到左上角一小块（看着像「图上大部分内容丢了」，实际是视口比图小 4 倍）。取 `--window-size=1587,1122`（A4 则是 1122×793）。

**缺角色时新增角色，别硬塞进近似的**。实测把区段标记先归 `dimension`/`extension`，L1 立刻多报 9 处：区段点划线被当尺寸线判四件套、2 mm 的区段短界线被当尺寸界线判「越界 1.0 mm」。新增 `zone-mark`（`{line, text}`，进 `MULTI_OK`）之后才归位。同类契约补漏：`tolerance-symbol` 要允许 `circle`（圆度符号就是个圆），`outline`/`roughness`/`section-outline` 要允许 `polyline`（与 `polygon` 只差闭合）。这些是**补漏不是放水**——判据仍要求元素类型与角色语义相符。

**别为了让某条闸转绿而改口径，但口径本身自相矛盾时要改**：C5 明确「多实例角色不要求逐个命名」，C7 却把它们算进分母，大齿轮因此卡在 59.4%（阈值 60%）。分母改成只算非 `MULTI_OK` 图元后 100%——这是把两条规则对齐，不是刷分。改口径时在代码注释里写明为什么，否则下一轮会被当成放水回滚。同一次改口径还带出一个更阴的错：C7 把 `tot` / `named` 重写成「非多实例」口径，后面的 `stat` 又拿这两个变量算全体覆盖率，结果 411 个图元、411 个都有 role，报告却印 `74.9%`（=308/411），看着像一百个图元没打角色。**收窄口径要另起局部变量（`c7_tot` / `c7_named`），不许覆盖报告层要用的统计量**；报告里显眼的百分比与分母对不上时，先查变量污染，别急着怀疑图。

### 3⅝、几何层（L2）：四处会让闸假绿的地方

**整条圆弧会被静默丢掉。** 只认 `M`/`L` 的取段函数把 `A` 命令跳过后，断面图的圆（`M 129.383 202A 22.5 22.5 0 1 0 129.383 216`，大半圆弧、不是 `<circle>`）根本不在轮廓集合里，剖面线端点被判「离轮廓 30 mm」——量的其实是「轮廓里没有这段弧」。按 SVG 规范做弧转中心参数化（端点、rx/ry、大弧与 sweep 标志齐全）再采样。

**弧必须在 SVG 原生坐标（y 向下）里解，别在自己的「图面向上」坐标系里套规范算法。** 把端点先翻成 y 向上、再按 SVG 规范算中心参数化，`sweep` 的方向正好反了：每条弧都被解成镜像——断面整圆跑到弦右侧 60 mm 外、最小二乘拟合出 r=25 而设计值 30.5，闸于是报「圆周不是整圆」「剖面线进缺口」「剖面线端点离轮廓 5 mm」，而图完全是对的。做法：`arc_pts((x1, y1), (x2, y2), …)` 全程用 SVG 坐标采样，**采完再 `H − y` 翻回**图面坐标；验收判据是「拟合圆心与设计圆心差 <0.05、半径等于 d/2、残差 <0.01」。圆拟合用**最小二乘（Kåsa）**，不用三点定圆：断面两段子弧的采样点近共线时三点解会给出差 5 mm 的假圆，把对的图判成错的。

**采样密度按弧长定，不能写死 8 段。** r=22.5 的大半圆切 8 段，弦高误差 1.15 mm，端点判据阈值 0.6 mm 时又变成假报「离轮廓 1.35 mm」。改成每 1 mm 弧长一个点（上限 64~96），误差降到 0.01 mm。

**`d` 里的数字不能按奇偶取。** `A` 有 7 个参数（rx ry rot large sweep x y），奇偶分组直接错位，包围盒算出 `(0,0)-(104,106)` 这种不可能的框，越界规则一次报 20 个假红。包围盒只从解析出的端点与采样点取。

**接缝判据要「每个端点找最近的另一个端点」，不是两两比较。** 两两比较会把同一个圆角自己的两端（r=0.3 的弦长 0.42 mm）报成细缝。正确顺序：先看这个端点有没有 ≤0.02 mm 的伙伴（接上了就过）→ 再判 0.02~0.5 mm（画漏的缝）→ >0.5 mm 是图形本来就分开。同一图元的两个端点不参与配对（那是圆弧的两端）。

L2 其余判据：圆弧 `r ≥ 弦长/2`（r 不够时浏览器会偷偷放大半径，图上圆角不是设计值）；圆弧端点落在相邻轮廓 ≤0.35 mm；`polygon` 画弧状点列（弦高 >1 mm）会自补一条没人画的弦；`A` 起终点重合的整圆应改 `circle`；剖面线两端贴轮廓 ≤0.6 mm；同组剖面线角度差 ≤0.5°、间距漂移 ≤15%；完全重合的重复线；越出内框。

### 3⅞、碰撞层（L3）：包围盒必须由浏览器给

**`getBBox()` 单独用是错的，`getCTM()` 也不能直接用**——后者含 viewBox→viewport 的缩放（`width="420mm"` 时是 3.78 倍），量出来是像素不是毫米。做法：SVG 内联进临时 HTML，页内脚本对每个元素累乘**元素自身到根 `<svg>`** 的变换（`el.transform.baseVal.consolidate().matrix` 逐级相乘），再把 `getBBox()` 四角变换后取轴对齐框。

**验证量对没对，看竖排文字的宽高比**：同一字体下竖排 `φ35 k6` 应是 3.44 宽 × 12.25 高，横排 `φ52` 是 7.00 × 3.44。宽高反了就是没乘旋转矩阵。

**取回结果不需要 puppeteer**：`JSON.stringify` 塞进 `<pre id="…">`，`chrome --headless=new --dump-dom` 打整份 DOM 再截取，`--virtual-time-budget=4000` 保证脚本跑完。

**阈值**：文字重叠 >0.15×0.15 mm 才算（更小的擦边是字体余量与抗锯齿）；文字压线相交 0.05 mm 就报；尺寸线「穿插」只认交点在两段**中段**（距两端都 >0.6 mm），共用节点与垂直布局不算。公差上下偏差之间 0.5 mm 的间距是排版惯例，判重叠不判间距就不会误报。

**视图—视图碰撞要有 `data-view` 才判**：用 bbox 聚类猜视图等于用猜测代替身份（ID-02 明令禁止），没有就报「未检查」并写明缺什么。

### 3Ⅸ、完备性（L2-10）：闸查不了「该画的没画」

L0~L3 全部以「图上已有图元」为前提。图上没有的东西，四层一起沉默——实测两次都是闸 0 不通过、用户看预览才发现：齿轮漏远侧可见轮廓 + 孔口竖线共 8 条；轴漏轴肩阶梯线中段 63 mm。

补法：生成器导出 `features.json`（契约见 `charter/features.schema.md`），检查器按**并集覆盖**比对。

- **线段**：取图上所有 `outline` / `section-outline` / `key-outline` 线段，两端垂直距离都 ≤0.15 mm 才算共线；投影区间合并允许 0.3 mm 接缝（圆角切点处本来就会把一条边拆成几段画）；覆盖率 <95% 算缺失，**报最大缺口的位置与长度**（「覆盖 2%，缺口 63.0 mm，起自 (167.0,122.5)」），不是只说一句「缺了」。
- **圆**：同心 ≤0.15 mm、同径 ≤0.15 mm。
- 清单里没有的线不报——清单是「至少要有」，倒角、圆角可以不写。
- 没有清单 → **未检查**，不判通过。

三条踩过的坑：

1. **清单必须从几何模型算，不能从 SVG 反推。** 反推永远自洽，等于只证明「抄得对」。轴项目的 `features()` 从 `X[]` / `R[]` 现算 16 条（10 母线 + 4 轴肩 + 2 端面），与画法代码完全分开；轴肩线声明为**一条完整竖线**（`MY−rr` 到 `MY+rr`），绘图拆成三段没关系，并集覆盖就算过。
2. **坐标系必须与 SVG 属性一致（y 向下）。** 生成器内部 y 向上时导出要 `fy = H − y`；两边混了就是「16/16 条全缺失、覆盖 0%」——出现「全部缺失」这种极端结果，先查坐标系，别查图形。
3. **判据只罚「缝隙」会奖励「缩短几何」。** L2-01 判「端点悬空 ≤0.5 mm」，为了让一条轴肩线通过，把它砍成两截短头，中段 63 mm 丢了：闸绿了、图错了，要等用户看图才发现。**修「缝隙」类报红前，先确认这条线本来该画多长**（依据在哪条 GB / 参考件）；能写成覆盖类判据（「该盖的都盖了」）的就别用「别留缝」。

**这一条的效力上限**：清单本身写错就挡不住（生成器以为轴肩线只该画到圆角切点，清单也照抄），所以它挡的是「想到了但画漏了」，挡不了「压根不知道要画」——后者只能靠画法规则（轴肩线画满大直径、基准三角底边贴线顶点朝外、齿部三线、全剖后远侧可见轮廓）。

### 3Ⅹ、变换层：把祖先矩阵乘进属性坐标，不让规则各自算

规则读的是图元属性；图元若被 `<g transform>` 包住，所有规则都在量**变换前**的坐标，而且量得自洽——不会报错，只会算错。修法只有一种：解析时递归走树、把祖先矩阵累乘，然后**改写属性**（`line` 两端点、`polygon/polyline` 顶点、`circle` 圆心+半径、`rect` 原点+宽高、`path` 的 `L/M` 端点与 `A` 半径）。改一处比改三十条规则稳，规则本身不必知道有变换。

- 只吃**相似变换**（`translate` / `rotate` / 等比 `scale` / `matrix`）：圆还是圆、弧还是弧，精确。非等比缩放或斜切下圆会变椭圆，属性模型表达不了 → 单独一条规则判**未检查并列出图元**，不许硬判通过、也不许静默按错坐标算。
- `rotate(a cx cy)` 要把旋转中心算进矩阵；不支持的写法（`skewX` 之类）抛错而不是当恒等。
- 验证配方：把整张图裹进 `<g transform>` 再跑，**逐条比状态**。`translate(0,0)` 与 `rotate(0 cx cy)` 必须与不包裹时完全一致（实测 29 条一致）。真平移一次会正当打红**清单类规则**（`features.json` 是绝对图纸坐标），这不是回归——图动了就得重导清单。
- 插包裹层时别用 `src[:src.index(">")]`：文件头有 `<?xml …?>`，会插到 XML 声明后面变成两个根节点（`ParseError: mismatched tag`）。先找 `<svg` 再找它自己的 `>`。

### 3Ⅺ、字形覆盖：字体栈判据看不见缺字；子集化对 PDF 零收益

字体栈规则（G-11/G-12）只能证明 CSS 里写了仿宋，**证明不了每个字符有字形**。缺字形时浏览器静默回退系统字体，图上看着像没问题——实测旧样例图内嵌的是残缺子集，`C`/`J`（图号）、`制`、`页` 四个字一直在回退。

判据只能查字体本身的 `cmap`：读图上全部 `<text>` 的字符，逐个查 `@font-face` 那个字体有没有字形，缺哪个报哪个（含 `U+XXXX` 与所在文字）。实现要点：

- 需要 `fontTools`。检查器自己的 python 不带三方包，**走子进程**调装了它的解释器（`uv venv ~/.venvs/fonttools` + `uv pip install --python ~/.venvs/fonttools/bin/python fonttools`；解释器路径可用环境变量覆盖，比如 `FONTTOOLS_PY`）。没装就判**未检查**并打印安装命令，不装懂。
- `@font-face` 可能是 `url(data:font/ttf;base64,…)` **内嵌字体**。先判 `data:` 前缀、base64 解码进 `BytesIO` 再读；正则直接取路径会把整段 base64 当文件名（`File name too long`）。
- **别把子集化当优化做进构建链**（实测三组对照）：15.2 MB 字体裁到 41 KB（191 字，371 倍），但导出的 PDF **字节数一模一样**（Chrome 打印时本来就按用字切子集），整页渲染 **0 / 8.9 M 像素差**。省下的只是本地开 HTML/SVG 的字体加载。任何「优化」先做对照实测（产物字节数 + 像素差），零收益不进链。

### 3Ⅻ、视图归属：只能人给，不能聚类

视图—视图碰撞要 `data-view`，而按 bbox 聚类猜归属是 ID-02 明令禁止的。补法是**人工声明**：`identify.py --views 视图区.json`（`{"视图":[{"名","区域":[x0,y0,x1,y1]}]}`），图元按包围盒中心落区；**区域重叠直接报错**，不开「就近归属」的口子；落不进任何区域的保持无 `data-view`（碰撞规则照旧判未检查）。旧图补完立刻能判，实测报出视图间图元相交。

**变异用例的两个配套坑**：①临时副本丢了相对路径的 `fonts/`，一切要读字体的规则都判「未检查」——看着像规则失效，其实是字体没找到；把底图目录的 `fonts/` 软链进临时目录。②测字形覆盖要注入**私用区字符**（`U+10FFFD` 这种），才证明这条判据有判别力。

### 4. 四态门禁，`未检查` 一律失败

`通过 / 不通过 / 不适用 / 未检查`。退出码只看前两个：**不通过 → 1，未检查 → 1，规则抛异常 → 记「未检查」并 1**。

反例：`report()` 返回 `len(bad) == 0`，于是「碰撞层未提供 --bounds」「规则异常」全都算成功，每次交付都是「9 通过 / 2 未检查」加 exit 0。这就是把门禁做成了装饰。

需要外部输入的检查（浏览器包围盒、渲染像素）要么脚本自己起 headless 浏览器拿（`getBBox` × `getScreenCTM`，见 SKILL.md 流程 7），要么显式失败；不许默认跳过还不报错。

### 5. 闸自己要被变异测试

每次运行（或 `--selftest`）注入一批已知错误，全部抓出才算闸可用；抓不出就先报「闸失效」，不要报「图通过」。

| 注入 | 应报 |
|---|---|
| 圆角控制点反向（凸成驼峰） | 圆角方向 |
| `C` 贝塞尔退化成折线（模拟输出层吞命令） | 路径命令 |
| 图号/材料换成别的题的值 | 串题 |
| 一条剖面线端点拉出断面外圆 | 剖面线 |
| 删一个箭头 / 尺寸线缩短 6 mm | 尺寸五要素 |
| 键槽母线缩短 7 mm（封口） | 开口槽 |
| 标题栏合并格被网格线切穿 | 标题栏 |
| 文字压线 / 越出内图框 | 碰撞、越界 |
| 复制一条线、共线叠合 | 重复线 |
| 段长文字与模型差 0.1 | 尺寸值 |
| 尺寸数字改成**图上另一个合法值**（41→40，图中有 φ40） | 尺寸值（按线配对才抓得住） |
| 界线外端拉长 20 mm（共用界线） | 界线越界 |
| 剖切字母改成别的字母（破坏成对与断面对应） | 剖切符号 |

**注入本身要断言生效**：`mutate()` 里先 `assert out != base`。写过的 `s.replace('data-role="datum"', 'data-role="datum"')` 是拿自己替换自己，函数留着、从未调用，还让自测报告看起来有 6 个用例。实测自测 6 例只抓住 1 例——那种闸报「通过」没有任何信息量。

**报「漏抓」时先分清是闸弱还是注入没落地**：两者症状一模一样。实测一轮 4 个注入 2 个漏抓，一个是真弱（41→40 被全图最近值放过去），一个是正则没命中（`y2="26"` 之前还隔着一个 `x2` 属性）。注入用精确子串替换（照 SVG 里那一段的原样写），改完 `grep` 回读一次确认落点变了，再判闸。

**变异用例要跟着判据一起长**：新写一条规则就加一条对应注入，否则那条规则永远是「通过」——图上真的错了也不会响。

**三种结果分开报，退出码要能区分**：`抓到` / `漏抓` / `注入未生效`。第三种是精确子串替换没命中（属性顺序记错、值多写了小数），图根本没变，跑出来和「漏抓」一模一样。**每次注入先比哈希，没变直接判失败、不往下跑**；漏抓与注入未生效都 exit 2，图有缺陷才是 exit 1。

**已确认的盲区单独登记，别凑一条规则遮过去**：没有判据的注入标 `known_gap`，报告写「已登记盲区：X（需要补规则 Y）」，不进失败计数但每次打印。半吊子规则把盲区盖住，比留着盲区更糟。

**按层跑**：`mutants.py -k L1` 只跑结构层（MUT-02「不重复跑无关用例」）；L3 的用例每次都要起 headless 浏览器，全量一次几十秒。

**别从别的脚本里调 `main()`**：它内部的 argparse 会吃掉调用方自己的 argv、直接 SystemExit(2)（看着像检查器崩了）。拆出 `run_all(layer=None, quiet=False)` 给 `check.py` 用，`main()` 只负责解析参数再转调。

## 6. 闸自身的盲区与失效方式（跑通 ≠ 可信）

验收一个闸，除了跑满五层，还要把下面五条当成必查项：

- **「尺寸线 / 界线 × 轮廓」没有判据**。L3 只判「文字×线」与「尺寸线×尺寸线」；尺寸线压在键槽长圆、剖面线上时四层全绿（实测一张 51/51 全通过的轴图，`φ61 h6` 的尺寸线正穿过键槽长圆）。要么另立规则（线×轮廓净距），要么交付前整页目视，并在报告里把它列进“未覆盖”。
- **规则↔条款映射没有校验**。每条规则的 `chapter` 字段没有任何程序比对；实测 46 条规则里 14 条指向 `rules.json` 中**不存在**的条款号（`GDT-xx`/`LINE-xx`/`TAB-xx`/`PART-xx`/`GEO-14` 这类），其余引用到的条款状态全是 X。后果：`check_charter.py` 报的「A 条款 10 条 / 覆盖率 6.9%」既不能当“已实现规则数”，也不能当“章程已落实”。报告要写「已实现规则 N 条；能追溯到 A 条款 0 条」，或给 `check_charter.py` 加一条「规则→条款 id 存在且状态为 A」的校验。
- **L4 的底图可能在仓库外**。`mutants.py` 用模块级常量指底图（样例 SVG 在 `draw/gear_pipeline`，另有两个 calc/svg 指向用户项目目录）。那些目录一清或改名，L4 不是报错而是**静默失效**（跑完 0，或把「注入未生效」当正常）。跑 L4 前先检查三个路径存在；要长期可用就把底图拷进 `charter/fixtures/` 并从常量指过去。
- **输入坏与图坏同码**。非法 JSON 的 `--calc` / `--features` 会让入口抛栈并 **exit 1**，与「有规则不通过」一模一样；自动化里分不清。调用前自己 `json.load` 一次，或给入口包 try 返回 2。
- **退出码契约要逐条验**，不能只看绿的那次：未知 `--part`、缺文件、坏 SVG 应均为 2；`devloop.sh` 除 build/截图失败外**恒 0**（图上有 ✗ 也 0），所以它只能当“跑完了”，不能当“过了”；交付前的最后一次检查必须是带 `--part` 的全参 `check.py`。
- **齿轮图的 P-13 线性集不含键槽宽**：`part/gear.py` 的 P-13 只把 `输入.几何.b`、`结构.hub_l`、`结构.web_t` 收进线性集，图上那条 `14 JS9`（键槽宽，出处是 GB/T 1095 与说明书键表）必定报「标注 '14 JS9' 的 14 不在计算书线性集 [21.6, 72.0, 72.0] 里」。**这是契约缺口，不是图错**：不要为消红删掉这条标注，也不要把 14 塞进 `web_t` 之类的字段凑数；要么在 `want_lin` 里补一项 `键.*.b`（改规则，注释写明为什么），要么在交付里把它写成已知缺口并给出 14 的出处。遇到这类「尺寸合法但不在契约集合里」的红，先把该尺寸的来源（标准表/说明书表）写出来，再决定改规则还是登记缺口。

## 规则写错比漏写更有害

闸报「不通过」时，**先核对期望值，再改图**。实测两类错判会把对的图改坏：

- 基准区间写成 `(xs[1]+1, xs[1]+13)`，落到了下一段（φ70）而不是轴承颈（φ60）→ 对的基准被判「不在轴承颈」。
- 竖线数按上一版结构期望 8 条，而参考件与当前图都是 7 条 → 按闸改就把对的结构改回错的。

判据：**该期望值能不能在参考件/计算书/标准表里找到出处**。找不到就是闸在猜，改闸，不改图。

## 闸证明不了什么（措辞纪律）

闸只能证明「排版与几何关系按判据成立」，证明不了画法、投影、符号语义、尺寸链是否合理。交付时说「闸 N 项通过 + 哪几项未覆盖」，不要说「已核/已验证」；画法正确性只有两条路：参考件源码逐元素对、人工目视整页 + 局部。

跑法：一条 `check.py 图.svg --calc … --fig-no …`（L0~L3，`--selftest` 连 L4）——顺序固定、末尾单列未检查清单。手动拆开才走 `identify --write`（缺身份时）→ `measure -o bounds.json` → `check_contract` → `check_rules --bounds` → `mutants`（改过检查器才跑）；**`--bounds` 漏传时 L3 六条全部变「未检查」，而汇总行仍写「N 通过」，看着像全绿**，这是这套闸最容易被误读的一处。
