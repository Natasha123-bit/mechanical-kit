## 返工最多的三条（键槽 / 剖面比例 / 字体与标题栏）

**① 轴主视图的键槽：长圆居中于轴线，高 = 键宽 b。** 不是从轮廓线往下挂。
手册图 20-6 原图逐像素量过：轴 φ60 轮廓 y=1781~2078（轴线 1929.5），长圆 y=1883~1973，
中心 1928 ≈ 轴线，高 90 px / 4.95 px·mm⁻¹ = 18.2 mm = 键宽 b=18。挂在轮廓上会被当成“乌龟壳”。
剖切符号照图 20-6 的 `G↓` 做法：短粗画 + 箭头 + 字母，画在键槽端部下方。

**② 剖面必须与主视图同比例（长对正）。** 主视图 1:2 时剖面也 1:2，不许 1:1 再挂个“（1:1）”。
剖面里键槽是**切进圆内的缺口**（宽 b、深 d−t1），孔圆在槽口处断开，其余 326.8° 是完整圆弧。

**③ 全图仿宋。** gbdraw 默认 `PingFang SC`，写盘后替换：
`font-family:'STFangsong','FangSong','华文仿宋','仿宋',serif`。
标题栏每个字都要**居中**（横竖都居中），写个 `cell(x1,x2,y1,y2,txt,h)` 包一层。

## 圆弧：手写 cos/sin 四次错在同一处

键槽长圆、孔圆缺口都靠角度参数，踩过的四个坑（均已发生两次以上）：

| 对象 | 正确写法 | 错写成什么 | 现象 |
| --- | --- | --- | --- |
| 长圆左端 | 90°→270°（cos 负，向外鼓） | 90°→-90° | 左端变成开口的括号 |
| 长圆右端 | -90°→90°（cos 正，向外鼓） | 与左端共用 90°→270° | 右端向内凹 |
| 轴剖面缺口（在上） | 106.6°→433.4° | 起点/扫角取反 | 缺口转到底部、圆变整圆 |
| 齿轮孔槽（在下） | 286.6°→613.4° | 同上 | 缺口转到了顶部 |

**像素采样只能验「我的脚本有没有画在我算的位置上」，验不了「这个位置该不该有」。**
它抓得住角度算反、坐标落错、渲染链拿到旧图；抓不住「这条线本来该不该画」「这个结构对不对」。
缺口用 20° 采样打点（缺口区白、其余黑）、长圆量左右极值是否在 x1/x2 —— 这属于**脚本自检**，
不是画法验收。别把它的通过当成图正确，更别在交付说明里写「像素核过」。

## 其他两类反复被指出的错

- **轴端倒角**：端面要**缩短**（r−c 到 −r+c），斜线从端面端点向外到轮廓端点；
  不能先画满高端面再从角上往里斜（那样倒角是“切进去”的）。轮廓线两端也要让出 c。
- **齿轮轴孔**：全剖里轴孔是矩形，**两侧孔口各一条竖线**（从槽底通到孔壁），
  不画就两头开著——这是被指过三次的漏线。

## 腹板式齿轮主视图：轮缘端面必须通到轮毂外圆

剖面里轮缘是一圈带，轮毂是一圈带，中间靠腹板连接。**腹板两侧那块空白腔是封闭的矩形**，
四边分别是：轮缘内表面（上）、轮毂外圆（下）、腹板侧面（内）、**轮缘端面（外）**。
轮缘端面只画 rim_in~ra 一段，就会留下一个三面开口的“口袋”——被反复指出“封闭线呢”就是这个。
`L(X0, Y(hub_r), X0, Y(ra))` 才对，两端都要。

子结构尺寸也要能自圆其说：d_a=294 时 rim_in=128.28、hub_r=56，腹板径向带宽 72 mm，
所以 4×φ40 布在 φ184 上（占据 72..112）才装得进去；照搬别的题的 φ40/φ184 要先验带宽。

## 结构画法

**腹板式齿轮（160 < d_a ≤ 500）**主视图全剖 = 三个矩形叠：
轮缘 `[X0,X1]×[rim_in,rf]`、腹板 `[WEB0,WEB1]×[hub_r,rim_in]`（剖到的减轻孔腔要断开留白）、
轮毂 `[HUB0,HUB1]×[key_top,hub_r]`。齿区 `rf..ra` 不剖、不画剖面线。
端视图另补**轮缘内径**与**轮毂外径**两条粗实线圆（从端面看是可见边）。

镜像下半区时**剖面线角度参数写绝对值**（`45 if sg>0 else 135`，孔腔 y 用 `hole_cy±hole_r` 而不是 `sg*`），
否则下半区会跨过轴线错画一大片。

**阶梯轴**：每段一个矩形，台阶面竖线从 `CY-rmax` 通到 `CY+rmax`（rmax = 两段较大半径），端面倒角 C2→1:2 下画 1 mm。

## 标注

- 直径：尺寸线自轴心向上下轮廓、箭头朝外，φ 值旋转 90°、`anchor="middle"`、离尺寸线 1.4~2.0。
- **直径尺寸线不得穿过键槽**：键槽段把 φ 标到段端（留 2 mm），或整段移到轴端外侧（画两条水平界线 + 竖尺寸线）。
- 键槽在主视图画长圆（胶囊）：**中心线与轴线重合**、高 = 键宽 b，两端半圆向外鼓，另加中心线穿过长圆中部。
  不要「顶边贴轴轮廓」那种画法：手册图20-6 实测长圆中心 1928 ≈ 轴线 1929.5，贴着轮廓画会被当成“乌龟壳”。
- **每个剖面在主视图上必须有剖切符号**：键槽中部一段粗短位置线（上下各一小段）+ 指向投射方向的箭头 + 字母，字母与剖面标签（`A—A`/`B—B`）同名；漏了这符号，剖面就是“不知从哪切下来的”。
- 同一处两条引出线（φ 与 Ra）夹角至少错开 15°，否则看成双箭头。
- 粗糙度：轴颈 Ra0.8、齿轮面 Ra1.6、孔 Ra1.6、端面 Ra3.2、其余 `Ra 6.3 (√)` 大一号写在标题栏上方。
- 基准符号放轴颈**正下方**（轮廓外），形位公差框引线指到该轴颈。

## 复核顺序（分两层：画法验收 / 脚本自检，别混）

**第一层——画法验收（决定这张图能不能交）**
0. **先把图上数据与计算书对一遍**：参数表（模数/齿数/螺旋角/中心距）与关键尺寸（齿宽 b₂、轴径序列、总长）逐项跟 `calc/*.json` 对，对不上就改图。
   照参考件版式时最容易连它那份数据一起搬过来（图上写 78、计算书是 92，图形再正确也是废图）。
1. 把参考件（手册图 / 已验收成品）与自己的图**并排**，逐项过：结构判据、每条轮廓是否首尾封闭、
   投影关系（长对正、剖面与主视图同比例）、标注是否齐（直径/槽深/形状位置公差/粗糙度有没有漏）。
2. 逐块问“这块实体的四边都画了吗”——空白腔也要四边封闭（轮缘端面、腹板侧面都算边）。
3. 过不了的项改完重跑第一层，不许用第二层的通过去抵。

**第二层——脚本自检（只证明渲染没出错）**
4. `python3 <脚本>.py` → SVG；Chrome `--print-to-pdf` 出 A3 PDF（`/MediaBox` 应为 `0 0 1191.12 841.92`）。
5. 出 PDF 后**先看 mtime** 确认是这一轮的；渲染链每步独立执行，别用 `&&` 串（前一步崩了会拿到旧图）。
6. PDF → PNG（本机无 pdftoppm，用 `/tmp/rpdf` 的 Swift+PDFKit 脚本，scale 1.6）；视觉复核只看**放大裁图**。
7. 像素采样只查“有没有画在我算的坐标上”：圆心采样查缺口区间、指定坐标打点查线在不在。

**交付措辞**：只写“改了什么、依据哪张参考图/手册图”，不要把第二层写成“已核/已验证”。
把“我量过了”当“我画对了”，是同一张图被反复退的直接原因。
