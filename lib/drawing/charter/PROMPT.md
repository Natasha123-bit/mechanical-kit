# 制图执行指令（给外部 AI 的入口）

> 本文件是章程的入口提示词，不含任何零件参数。条款正文见 `../CHARTER.md`，
> 接口签名见 `api.md`（由代码反射生成，以它为准）。

## 工作顺序

1. **读章程**：`../CHARTER.md` 第 0 章先看条款状态的含义。标 `[X]` 的条款**没有自动检查**，
   交付时只能写“人工核对”，不得写成“已符合”。
2. **核接口**：打开 `api.md`，按里面的签名写代码。不要凭记忆写 import，
   也不要把函数名当成标准符合性的证明（GEN-05）。
3. **建模型**：按第 4 章分六层（part / geometry / precision / views / layout / checks）。
   每个特征给稳定 `feature_id`，每个尺寸记被测要素与来源。同一结构只存一份参数。
4. **选表达**：先写表达方案（视图名称、类型、观察方向、要表达的特征、比例、对应关系），
   再画线（VIEW-01）。剖视图与断面图不是同一种东西（VIEW-03）。
5. **出图**：用 `lib/drawing` 的图元与 `SemSheet`，每个图元带 `data-role`/`data-name`，
   能给 `data-feature` 就给。不要拼 SVG 字符串。
6. **跑检查**：`check_contract.py`（L0）必跑；其余层按当前实现能跑多少跑多少，
   跑不了的写“未检查”，不许当成通过（GEN-10）。
7. **交付**：SVG + 生成脚本 + 模型参数 + 核查记录 + 证据。核查记录里必须包含
   实际执行了哪些检查、哪些没执行、X 状态的条款怎么处理的。

## 不许做的

- 不许引入其他任务的参数、图号或材料（GATE-01）。
- 不许为了消除冲突而缩小文字、遮盖轮廓、删视图（GEN-08）。
- 不许用旧截图判断新图（GEN-07）。
- 不许把“程序跑通了”说成“图已经正确”（CHK-03、MUT-03）。
- 不许在图上偷改数值来让几何“成立”（GEN-09）。

## 出问题时

先判断是哪一类，再改：

| 现象 | 先查什么 |
|---|---|
| 尺寸对不上 | 是不是有多份参数（GATE-02） |
| 槽口朝向不对 | 视图坐标与观察轴有没有定义（VIEW-07） |
| 圆角看起来像但放大有折角 | 是不是折线或输出了非圆弧命令（GEO-01、GEO-02） |
| 引线穿字 | 有没有给标注留包络（LAY-02） |
| 字体变宽或被替换 | 字体是否真的加载（FONT-01、FONT-04） |
| 改完预览还是旧图 | 预览与 SVG 是否哈希绑定（RUN-07） |

常见错误的完整对照见 `../CHARTER.md` 附录 A。
