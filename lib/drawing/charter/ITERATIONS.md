## 2. 工具链

### `check.py` — 一条命令跑完 L0~L3

```bash
python3 lib/drawing/charter/check.py 图.svg --calc calc.json --fig-no CS2-01
python3 lib/drawing/charter/check.py 图.svg --selftest     # 连 L4 一起跑
```

顺序固定为 measure → L0 → L1~L3，末尾单列“未检查”清单。
退出码：0 无“不通过” / 1 有“不通过” / 2 检查器自身异常或 L4 漏抓。

### `measure.py` — Chromium 量真实包围盒

`getBBox × 根变换矩阵`，坐标为图面毫米（只累乘元素到根 `<svg>` 的变换，不含
viewBox→viewport 缩放）。每条 bbox 带 `view` 字段（取自 `data-view`），供裁剪与 L3-06 使用。

不传 `--bounds` 时 L3 全部判未检查；`check.py` 固定执行顺序即为此。

### `identify.py` — 补图元身份

旧图常缺 `data-role` 或使用自造角色。`--write` 写回并保留 `.orig` 备份，只写 `data-*`
属性，不改几何与样式，改后渲染像素与改前一致。

### `mutants.py` — 注错反测

```bash
python3 lib/drawing/charter/mutants.py         # 全部 18 个
python3 lib/drawing/charter/mutants.py -k L2   # 只跑几何层（MUT-02）
```

### `devloop.sh` — 改图循环

```bash
# 在项目目录内执行，生成器与图按当前目录解析
mdkit/lib/drawing/charter/devloop.sh build_shaft.py \
    --svg 中间轴零件图.svg --calc calc.json --fig-no CS2-01
```

build → check → 整页截图 → 按 `data-view` 裁局部，产物写入图所在目录的 `预览/`。
实测 2.06 秒（420×297mm，5 张局部）。

裁剪只认 `data-view`，不按 bbox 聚类推断视图归属（ID-02）；无锚点时只出整页并提示补锚点。

## 3. 完备性：L2-10 + features.json

### 背景

两次绘图实测中，章程全绿而图纸存在漏画：

| 项目 | 漏画内容 | 章程当时的结论 | 发现途径 |
|---|---|---|---|
| 齿轮测试1 | 腹板孔口 4 条竖线 + 远侧可见轮廓 4 条 | 28 通过 / 0 不通过 | 交付后目视 |
| 多段轴测试1 | 轴肩阶梯线中段（因消除 T 型接点被拆成两截） | 33 通过 / 0 不通过 | 交付后目视 |

原因：其余规则都以“图上已画出的图元”为前提，缺失的图元不在判定范围内。
L2-01 只判端点是否接上，整条线缺失或中段缺失时无输出。

### 做法

生成器导出 `features.json`（格式见 `features.schema.md`），检查器反查“清单声明存在、图上没有”：

- 线段按**并集覆盖**判定：图上可拆成数段绘制（圆角切点处本就拆段），覆盖率 ≥95% 为通过
- 覆盖率不足时报告最大缺口的**位置与长度**
- 清单中未列出的线不报（清单是“至少要有”，倒角、圆角可不写）
- 无清单时判**未检查**，不判通过（CHK-08）

**清单必须由生成器的几何模型导出，不可从 SVG 反推**：反推结果永远自洽，无法发现漏画。

### 实测

轴项目 `build_shaft.py` 从 `X[]/R[]` 导出 16 条（10 条母线 + 4 条轴肩 + 2 条端面）：

| 情况 | L2-01 | L2-10 |
|---|---|---|
| 正常图 | ✓ 116 个端点都接上 | ✓ 清单 16 条图上都有 |
| 删除 shoulder2.mid（63mm 中段） | **✓ 114 个端点都接上了** | **✗ 覆盖 2%，缺口 63.0mm，起自 (167.0,122.5)** |

第二行复现了轴项目自检记录第 ④→⑩ 条的成因链：为消除 T 型接点将轴肩线拆成两截，
中段丢失，而 L2-01 仍判通过。

## 7. 已知局限

1. **L1/L2 不解析 `transform`** — 按属性坐标判定，带 transform 的图元结果不准。L3 通过 measure 规避，L1/L2 尚未处理。
2. **L3 只判 `<line>`，圆与路径未覆盖** — 齿轮图 15 个整圆、轴图 4 个整圆均未参与碰撞检查。
3. **L3-01/05/06 使用外接盒** — 圆的外接盒面积比圆大 27%（1 : π/4），存在误报与漏报风险。
4. **L3-06 依赖 `data-view`** — 无锚点的旧图恒为未检查。
5. **键槽开口方向为已知盲区** — 25 条规则均未覆盖，L4 中标记 `known_gap`。
6. **清单本身错误无法发现** — L2-10 的效力上限取决于清单编写者对画法的理解。
7. **几何判定的前提是坐标正确** — bbox 来自浏览器；若 SVG 使用 `clipPath` 或滤镜，框可能偏移。
8. **字体只核引用，未核字形墨迹** — 碰撞判定使用字宽近似，非真实轮廓。

### 8.2 L2-14 覆盖面

轴项目自检记录第 ④→⑩ 条构成一对因果：L2-01 判“端点有无细缝”，为消除 T 型接点将轴肩线
拆成两截成为通过检查的最省事做法；检查通过，图纸错误。

新增 L2-14：由轴线位置与各段半径正向计算“该竖线上应被轮廓覆盖的区间”，实测不足即报。
判据由“别留缝”改为“该盖的都盖了”。约 80 行，依赖 8.1 的段表读取。

### 8.3 L3 支持圆和弧

`L3-02` 当前证据行为“73 个文字都没压轮廓（57 条轮廓线）”，57 条均为 `<line>`；
齿轮图 15 个整圆、轴图 4 个整圆未参与。项目侧 `S-12` / `Z-09` 已实现完整判定：

- `<circle>`：判多边形各边到圆心的最近/最远距离是否夹住半径
- `<path>` 的 `A` 命令：按 0.5mm 弧长采样成折线
- `<path>` 的 `L/M`：按折线处理
- `<rect>`：四条边参与
- `rotate(θ,cx,cy)`：角点旋转后判定

移植进 `check_rules.py` 替换 L3-02/03 现有实现，约 150 行，需回归 6 条 L3 规则。

### 8.4 features.json 推广到齿轮项目

`build_gear.py` 增加 `features()`：主视图的轮缘内孔端面竖线（4 条）、腹板孔口竖线（4 条）、

每条 `说明` 写明该线的由来。约 60 行。

### 8.5 L1-11 键槽开口方向

L4 的 `keyway_flip` 用例将断面键槽开到轴线另一侧，25 条规则均未报出，已标 `known_gap`。
判据为：键槽轮廓应位于轴线一侧，且与主视图剖切位置指示方向一致。约 50 行，
难点在于“方向一致”的判据定义。

### 8.7 L1/L2 解析 transform

`Ctx` 读取图元属性坐标，图元位于 `<g transform>` 内时 L1/L2 判定基于变换前坐标。
两个选择：`Ctx` 累乘祖先 transform 矩阵（约 100 行）；或 L1/L2 改用 measure（尺寸线、
界线需要端点而非包围盒，仍需自行变换）。当前两个实测项目的图均无 `<g transform>`，非紧急。

### 8.8 L3-06 的 data-view 依赖

L3-06 需要 `data-view`；两张样例图无此属性，恒为未检查。`identify.py` 可补 `data-role`，
但 `data-view` 属于视图归属，按 ID-02 不得由 bbox 聚类推断。约定生成器一律输出 `data-view`，
旧图接受未检查并在报告中写明。

### 8.9 字体子集化 / 真机打印

本机无 `fontTools`/`pyftsubset`，未做字体子集化（PDF 中 11 个子集由 PDFKit 自动切分）；
线宽 0.5/0.25mm 仅为 CSS 值，未用打印件核对；未在 Acrobat / Inkscape / WPS 验证回退。

## 9. 明确不做的

| 事项 | 理由 |
