会把尺寸界线也捞进来——φ126h11 那条界线就带 `feature=tip`）。

## 2. 工具链

### `check.py` — 一条命令跑完 L0~L3

```bash
python3 lib/drawing/charter/check.py 图.svg --calc calc.json --fig-no CS2-01
python3 lib/drawing/charter/check.py 图.svg --selftest     # 连 L4 一起跑
python3 lib/drawing/charter/check.py 图.svg --json 门禁/check.json   # 落盘：sha256 + 字节数 + 逐条证据
python3 lib/drawing/charter/check.py 轴图.svg --calc calc.json --part shaft   # 加轴类画法规则包
python3 lib/drawing/charter/check.py 齿轮图.svg --calc calc.json --part gear  # 加齿轮画法规则包
```

顺序固定为 measure → L0 → L1~L3，末尾单列“未检查”清单。
退出码：0 无“不通过” / 1 有“不通过” / 2 检查器自身异常或 L4 漏抓。

### `measure.py` — Chromium 量真实包围盒

`getBBox × 根变换矩阵`，坐标为图面毫米（只累乘元素到根 `<svg>` 的变换，不含
viewBox→viewport 缩放）。每条 bbox 带 `view` 字段（取自 `data-view`），供裁剪与 L3-06 使用。

不传 `--bounds` 时 L3 全部判未检查；`check.py` 固定执行顺序即为此。

### `identify.py` — 补图元身份

旧图常缺 `data-role` 或使用自造角色。`--write` 写回并保留 `.orig` 备份，只写 `data-*`
属性，不改几何与样式，改后渲染像素与改前一致。

### `mutants.py` — 注错反测

```bash
python3 lib/drawing/charter/mutants.py         # 全部 24 个
python3 lib/drawing/charter/mutants.py -k L2   # 只跑几何层（MUT-02）
```

### `devloop.sh` — 改图循环

```bash
# 在项目目录内执行，生成器与图按当前目录解析
mdkit/lib/drawing/charter/devloop.sh build_shaft.py \
    --svg 中间轴零件图.svg --calc calc.json --fig-no CS2-01
```

build → check → 整页截图 → 按 `data-view` 裁局部，产物写入图所在目录的 `预览/`。
实测 2.06 秒（420×297mm，5 张局部）。

裁剪只认 `data-view`，不按 bbox 聚类推断视图归属（ID-02）；无锚点时只出整页并提示补锚点。

## 3. 完备性：L2-10 + features.json

### 背景

两次绘图实测中，章程全绿而图纸存在漏画：

| 项目 | 漏画内容 | 章程当时的结论 | 发现途径 |
|---|---|---|---|
| 齿轮测试1 | 腹板孔口 4 条竖线 + 远侧可见轮廓 4 条 | 28 通过 / 0 不通过 | 交付后目视 |
| 多段轴测试1 | 轴肩阶梯线中段（因消除 T 型接点被拆成两截） | 33 通过 / 0 不通过 | 交付后目视 |

原因：其余规则都以“图上已画出的图元”为前提，缺失的图元不在判定范围内。
L2-01 只判端点是否接上，整条线缺失或中段缺失时无输出。

### 做法

生成器导出 `features.json`（格式见 `features.schema.md`），检查器反查“清单声明存在、图上没有”：

- 线段按**并集覆盖**判定：图上可拆成数段绘制（圆角切点处本就拆段），覆盖率 ≥95% 为通过
- 覆盖率不足时报告最大缺口的**位置与长度**
- 清单中未列出的线不报（清单是“至少要有”，倒角、圆角可不写）
- 无清单时判**未检查**，不判通过（CHK-08）

**清单必须由生成器的几何模型导出，不可从 SVG 反推**：反推结果永远自洽，无法发现漏画。

### 实测

轴项目 `build_shaft.py` 从 `X[]/R[]` 导出 16 条（10 条母线 + 4 条轴肩 + 2 条端面）：

| 情况 | L2-01 | L2-10 |
|---|---|---|
| 正常图 | ✓ 116 个端点都接上 | ✓ 清单 16 条图上都有 |
| 删除 shoulder2.mid（63mm 中段） | **✓ 114 个端点都接上了** | **✗ 覆盖 2%，缺口 63.0mm，起自 (167.0,122.5)** |

第二行复现了轴项目自检记录第 ④→⑩ 条的成因链：为消除 T 型接点将轴肩线拆成两截，
中段丢失，而 L2-01 仍判通过。

## 4. 两份字段契约

| 文件 | 管什么 |
|---|---|
| `calc.schema.md` | 计算书 JSON：`键`（键宽/槽深）、`材料45`（材料/热处理）两段 |
| `features.schema.md` | 要素清单：线段/圆、坐标与 SVG 同一套（y 向下）、容差、判据、边界 |

缺段时报告“计算书缺 键 段（见 calc.schema.md）”并列出实际顶层键。
**不提供多结构适配器**：字段名只能靠猜，猜错等同于用其他题目的键值比对本图键槽，
比“未检查”更不可靠。

### 8.3 L3 支持圆和弧 —— 已完成（2026-10-28）

做法不是搬 `S-12` 的“多边形夹半径”，而是统一成**线宽胶囊 + 净距**：

- `capsules(ctx, roles)` 把 `line`、`path` 的 `L`/`M`/`A`（弧用 `_arc_points` 采样成折线）、
  `circle`（72 边）、`polygon`/`polyline` 都拆成 `(x1,y1,x2,y2,half,role)`，
  `half` 由 `class` 查 `HALF_W`（粗 0.25 / 细 0.125 / 尺寸 0.10 / 剖面 0.09）
- `box_cap_dist()` 给矩形到胶囊的**净距**，`< 0` 才算压上；证据行报最小净距
- 文字框来源：图旁 `inkbox.json`（实测墨迹）优先，否则浏览器 bbox 按 `0.10×字号` 内缩
  —— `getBBox` 含字身侧距与上下留白，比墨迹宽 0.2~0.4mm，不内缩会把“引线贴字边”判成压线
  （首版就这么误报了 `R1`，净距 −0.03，实为布框留白）

实测：

| 图 | L3-02 证据 | 结论 |
|---|---|---|
| 多段轴测试1 | 73 个文字 / 胶囊 593 段 / 最小净距 1.35mm | 通过 |
| 样例-大齿轮 | 1 处 `0` 压细实线，净距 −0.12mm | 旧图真缺陷，被新覆盖面抓出 |

反测：新增 `text_on_arc`，把 `41` 挪到断面整圆弧 45° 处；最近胶囊两端点到圆心距离实测
都是 22.500，确认命中的是弧而不是邻近直线。

遗留：`<rect>` 未单列（矩形图的轮廓在样例里是 4 条 `line`）；`<g transform>` 仍不支持，见 8.7。

### 8.4 features.json 推广到齿轮项目 —— 已完成（2026-10-28）

做法没照原计划写一个 `features()` 函数，而是**在 `seg()` / `circ()` 出口处顺手记**：
凡是带 `data-feature` 且角色是 outline / section-outline / key-outline 的图元，画的时候
就落一条进 `FEATS`，`main()` 里与 SVG 同时写 `features.json`。这样清单与图必然同源同时
（`features.schema.md` 的硬要求），也不存在“事后补写等于抄一遍”的问题。

### 8.5 L1-11 键槽开口方向 —— 已完成（2026-10-28）

难点果然是“方向一致”怎么定义，最终选了**同图自洽约定**并写进规则文档：
**剖切箭头指向 +x，缺口就开在 +x**（相当于把断面按箭头方向转正）。这是约定，不是国标原文，
所以规则名和证据行都写明“一致”，不写“正确”。

实现靠几何，不靠 `data-name`（样例用 `sec.4`/`cp.2`，自己的图用 `Ⅱ`/`Ⅳ`，配对必错）：

1. `section-outline` 按 8mm 邻接聚成断面簇
2. 圆心取最近的「中心线十字」交点（竖线 × 横线，且交点落在两条线的跨度内）
3. 开口侧 = 离圆心最远的那条竖直 `section-outline` 线在哪一边
4. 箭头方向 = `cutting-plane` 里**不竖直**的那条细线（粗短线是剖切位置线，不参与）；
   上下两支方向不一致、或 +x/−x 混用，一律判未检查，不硬判

实测：轴图「2 个断面（A、B）缺口开 +x，剖切箭头 +x，一致」；样例
「2 个断面（sec.6、sec.5）缺口开 +x，箭头 +x，一致」。反测 `keyway_flip`
（125→91）由“已登记盲区”转为真抓：「sec.4 缺口开 −x，箭头指向 +x」。

遗留：不校验三维真实方位，也不判“缺口该在 12 点还是 3 点”，只判图内自洽。
