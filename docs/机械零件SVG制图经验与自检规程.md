# 机械零件 SVG 制图经验与自检规程

日期：2026-10-28

用途：供 AI 根据已经明确的零件结构与技术要求，使用工作库生成机械零件 SVG 图，并在交付前完成画法、投影、几何、标注及渲染检查。

本文只保存通用画图经验，不包含任何题目的尺寸、材料、型号、公差选值或计算结果。文中的字号、线宽等数字属于纸面制图配置，字母公式属于抽象几何关系。文档用于建立可复核的出图流程；“检查通过”必须对应已执行的检查，不以一句提示词代替验证。

## 1. AI 开始执行时必须遵守的规则

1. 使用程序化矢量绘图表达工程图，不用图像生成模型绘制需要准确尺寸、公差和文字的正式零件图。
2. 先核对输入结构，再选择表达方案；不要先摆一张好看的图，然后补结构和尺寸。
3. 所有视图、断面、尺寸值和技术要求引用同一份最终参数。不要分别为主视图、断面和参数表抄三套数据。
4. 图形按模型投影，标注按特征关联，版面按纸面尺寸安排。三者分开管理。
5. 使用工作库时，先检查当前版本的函数签名、实现及输出，不把函数名称当作标准符合性的证明。
6. 分开检查“这条线应不应该存在”和“这条线有没有画在预定位置”。前者是画法审查，后者是实现检查，二者都要通过。
7. 每次修改后重新生成并检查当前版本，不用旧截图判断新 SVG。
8. 不通过缩小文字、遮盖轮廓或删除必需视图来消除布局冲突。
9. 发现输入几何无法成立时，记录具体冲突。需要改变设计的，先按授权范围处理并同步源数据，不能只在图上偷偷改值。
10. 未执行、未覆盖的检查写“未检查”，不能把空的错误列表自动解释为全部合格。

## 2. 画图前先建立输入清单

至少明确下表内容，再开始正式出图。只缺署名、单位名称等非几何字段时，可以留空；缺失会影响结构表达的关键输入时，不猜测补齐。

| 输入类别 | 必须明确的内容 |
|---|---|
| 零件身份 | 名称、图号、版本、零件图或装配图的类型 |
| 实体结构 | 外形、孔、槽、台阶、圆角、倒角、螺纹、退刀槽等真实特征 |
| 空间关系 | 各特征的轴向位置、周向角度、方向、对称关系及相交关系 |
| 尺寸含义 | 数值对应哪两个面、哪条轴线或哪一个导出要素 |
| 精度要求 | 尺寸公差、配合、几何公差、基准及表面结构要求 |
| 其他要求 | 材料、热处理、表面处理和其他已确认的制造要求 |
| 图纸要求 | 幅面、装订形式、投影法、比例、标题栏样式及交付格式 |
| 依据 | 用户要求、适用标准版本、指定教材图例或已确认参考图 |

为每项关键输入保存来源及状态：`已确认 / 待确认 / 推导值`。参考图只用于迁移适用的表达方法和版式，不携带参考零件的参数。

不得把“通常有中心孔”“一般用这种配合”“轴端常有螺孔”转化为实体特征。某个孔属于相邻轮毂，也不能画到轴上。

## 3. 标准依据必须先于画法判断

按任务所要求的标准体系及版本核对图幅、比例、字体、图线、视图、尺寸、几何公差、表面结构和标题栏。若依据是教材，记录书名、图表号和印刷页；核对 PDF 物理页时单独登记映射，不跨书套用固定页码偏移。

对容易误判的表达，应查看同类结构的原图局部，先列出可见边、不可见边、剖切边及省略规则，再画图。整页缩略图和 OCR 文字不足以确认小型制图符号。

以下三类内容必须区分：

| 类别 | 例子 | 使用方式 |
|---|---|---|
| 标准表达规则 | 图线用途、尺寸注法、基准和公差框含义 | 按适用标准核对 |
| 绘图实现约定 | 图纸坐标向上、毫米用户单位、元素角色名称 | 在脚本中统一并明确记录 |
| 某次图样的选择 | 视图数量、断面朝向、具体比例、标注位置 | 重新依据当前零件确定 |

历史工作库说明可能混有旧接口、旧版式和某个渲染器的问题。不得直接推广成“所有图都只能这样画”。未核实标准现行性时，说明按哪份资料绘制，不宣称已符合全部现行标准。

## 4. 建立唯一几何模型，消除视图不一致

### 4.1 推荐的数据组织

将数据至少分为六层，保存为结构化文件或等价对象：

```text
part       零件身份、版本、数据来源
geometry   实体特征及三维位置；二维特例也保留方向信息
precision  尺寸公差、配合、表面结构、功能范围、基准与几何公差
views      观察方向、剖切平面、剖切方向、比例及视图名称
layout     图幅、图框、视图原点、文字区、尺寸区、标题栏预留区
checks     期望关系、采样位置、碰撞规则和适用例外
```

每个特征设置稳定的 `feature_id`。每个尺寸记录被测要素、测量方向、数值来源和控制/参考属性；不要只有一段孤立文字。

例如，一个槽应只有一份槽宽、槽深、长度、位置和方向；主视、端视、断面及尺寸文字均从它生成。参数表存字段引用和格式，不另存一套相同数值。

### 4.2 分开管理三种坐标

| 坐标 | 用途 | 注意事项 |
|---|---|---|
| 模型坐标 | 零件真实几何与尺寸关系 | 与视图摆放无关 |
| 图纸坐标 | 几何投影后在纸上的毫米位置 | 明确原点及坐标轴方向 |
| 渲染坐标 | SVG、浏览器或 PNG 中的位置 | 包含翻转、缩放、偏移及像素密度 |

一个视图可用下式表示，其中 `e_u、e_v` 是视图平面的单位方向，`s` 是绘图比例：

```text
u = u0 + s × dot(p − o, e_u)
v = v0 + s × dot(p − o, e_v)
```

工作库 `Sheet` 默认采用图纸 y 向上，输出 SVG 时转换为 y 向下。不能在几何层翻转一次，又在输出或核查层重复翻转。旋转角度在两种坐标中也要统一约定。

几何尺寸随视图比例变化；纸面字高、箭头大小、线宽和标注间距分别管理，不随零件整体缩放。

### 4.3 功能分区不是实体台阶

同一公称直径上可以存在不同配合、粗糙度或表面处理区段。应通过适用的范围表示、区段字母、轴向界限或局部要求表明确归属，不能为表现精度差别而凭空增加实体直径变化。

区段应完整覆盖其功能范围，明确未单注区域适用什么要求，避免同一表面同时受两条互相矛盾的总注控制。

## 5. 正确选择视图、剖视与断面

### 5.1 先写表达方案，再画图

对每个视图先登记：名称、类型、观察方向、需要表达的特征、比例，以及与其他视图的对应关系。视图数量以清晰、完整表达结构为准；不要为了凑“三视图”增加重复视图，也不要把必要的局部结构省掉。

| 表达方式 | 表达重点 | 常见误用 |
|---|---|---|
| 外视图 | 沿观察方向看到的投影轮廓及适用的内部隐线 | 按纵剖轮廓删掉真实可见圆棱 |
| 剖视图 | 剖开后看到的切口及规定保留的后方投影 | 只画切面，遗漏后方应有结构 |
| 断面图 | 通常表示剖切平面中的截面形状；标准规定的特殊结构按相应剖视规定表达 | 无依据混入后方轮廓，或忽略特殊结构的规定画法 |
| 局部放大图 | 单独说明难以表达的小结构 | 放大了几何却未标比例或对应位置 |

不要把所有含剖面线的图统称为“剖面”。特别区分剖视图和断面图。

断面的特殊情形不能遗漏：剖切平面通过由回转面形成的孔或凹坑轴线时，以及非圆孔使断面完全分离等标准规定情形，应按相应剖视规定表达。对这些情况，不能用“断面永远只画切面”删掉规定应保留的线。

### 5.2 统一投影法和观察方向

基本视图按所选投影法配置，并检查长对正、高平齐、宽相等。采用第一角投影时，俯视图置于主视图下方，右视图置于主视图左方；不能混用第三角的排列。

需要投影法识别符号时，依据标准图例绘制，不凭记忆翻转圆台和同心圆。第一角常用符号为圆台侧形在左、同心圆在右，侧形左小右大；仍应核对所用图例和图纸方向。

断面槽口朝上、朝下、朝左或朝右，必须由真实特征方向与剖切观察方向推导，不能由版面空白决定。先定义视图的水平、竖直及观察轴，再变换模型中的槽向量。采用旋转表达时，按适用规则注明。

### 5.3 剖切标注必须能追溯

剖切位置线、箭头、字母和断面/剖视图名称相互对应；只有满足标准允许的省略条件才省略。箭头方向不能为了给文字让位而反转。

剖切平面必须实际穿过要表达的特征。断面直径、槽宽、槽深和方向来自该位置的实体，而不是从附近另一段取值。

默认可用相同比例减少对应错误；需要不同的允许比例时明确标注，并按各自比例还原模型量进行比较。不能把“本次选择同比例”写成“断面永远不允许放大”。

### 5.4 轴、孔槽及薄壁结构的条件性规则

- 正对槽口观察、且槽型确为封闭圆头槽时，主视投影才可能是与轴线对中的长圆；开口槽、侧向槽及其他刀具成形槽不能照搬。
- 断面槽口是材料被去除的区域。缺口处不得残留穿过槽口的完整外圆，也不得填剖面线。
- 非剖外视中的可见圆棱投影，与纵剖图中的实体边界不同。台阶竖线是否通长，应先判断可见性和视图类型，不能统一画成通长或上下两小段。
- 轴、键、紧固件、肋和轮辐等在特定纵向剖切条件下有规定画法。按各自条件核对，不能把“不剖”规则用于所有截面或所有零件。
- 螺纹、齿轮、花键、轴承等有专门规定画法，不能按普通实体轮廓推测其全部线条。
- 同一零件的剖面线按适用规则保持方向、间距一致；多个分离剖切区域也应能读作同一零件。相邻不同零件需要区分时，再按规则调整方向或间距。线族不得穿越孔槽，方向与主要轮廓近似平行时应选择标准允许的其他角度。

## 6. 先检查几何能否成立，再修饰轮廓

### 6.1 圆角和倒角应是真实几何

圆角使用与相邻表面相切的圆弧，保存切点、圆心和半径。构造完成后检查端点连接和切线连续性，不用折线拐弯或遮盖矩形伪装圆角。

倒角会改变原边界：端面、母线等应在倒角端点处截短，再连接斜线。不能先画完整尖角，再往尖角里叠两条斜线。

开放圆弧不得使用会自动闭合的 `polygon`，否则会出现连接两端的多余弦线。采用原生圆弧，或在验证过的输出层使用开放折线；闭合多边形用于有意闭合的区域和箭头。

圆弧扫角要检查起点、终点、圆心、切线及极值位置，不能只确认半径正确。完整圆优先用圆图元，避免用起终点重合的单段圆弧命令表达。

### 6.2 极限尺寸也必须可成形

对常见的直角轴肩、较小圆柱面与肩面之间的四分之一圆内圆角，可以进行以下检查：

```text
最小径向台阶 h_min = (大径最小值 − 小径最大值) / 2
要求 R_max ≤ h_min
```

这只是该类圆角的必要几何条件。还应检查轴向空间、相邻圆角占用、刀具可达性，以及是否必须保留定位环面。`R_max = h_min` 可能恰好没有剩余直线定位面，不能仅凭上述不等式判定定位功能合格。

同一短段两端都有过渡时，检查两侧实际切线占用之和不超过可用长度。非直角、非圆弧或复合过渡，按真实轮廓求包络，不直接套上述式子。

槽端、孔边、退刀槽和肩圆角之间的最小净距，也按最不利公差组合检查。仅对轴向占用恰为半径的直角四分之一圆过渡，可简写为：

```text
最小轴向净距 = 最小端距 − 最大圆角半径
```

一般情况应减去过渡的实际轴向包络。净距需要多少由功能及工艺依据确定，不沿用其他零件的经验数值。

## 7. 图幅、比例、线型和字体

### 7.1 按完整图面包络选择幅面

先预留图框、标题栏、技术要求、参数表、尺寸带及视图间距，再判断几何能否放下。不能只拿零件外廓长度与纸宽比较。

图框边距同时取决于幅面和是否留装订边，应从同一套适用规则取得。不要混用不同幅面的边距，也不要把简化标题栏冒称为完整标准式标题栏。

比例从适用的标准比例系列选取，并在标题栏及需要的局部视图处正确标明。不得非等比拉伸图形；尺寸数字始终表示真实尺寸，不是纸上测量值。

图面拥挤时，优先调整布局、图幅或允许的比例，保持文字和符号的纸面可读性。

### 7.2 线型按语义分配

| 要素 | 常用线型，最终按适用标准核对 |
|---|---|
| 可见轮廓、移出断面轮廓 | 粗实线 |
| 尺寸线、尺寸界线、引出线、剖面线 | 细实线 |
| 轴线、圆心线、对称中心线 | 细点画线 |
| 必要的不可见轮廓 | 细虚线 |
| 剖切位置、局部范围及特殊辅助表示 | 按对应表示法选取，不能混用 |

普通机械图样可采用粗细约为 2:1 的一致组合，例如纸面 0.50/0.25 mm；具体组合按所选标准和图幅确定，不是全行业只允许这两个数值。

中心线应适当伸出轮廓；圆心位置以长画相交。短范围点画线要检查实际节距，避免只剩一条长划而失去点画特征。线型重合时按标准优先次序表达，不把不同线型无条件全部叠上去。

### 7.3 字高和可读性是纸面约束

机械图样汉字使用符合要求的仿宋体，通常不小于 3.5 mm；尺寸数字可统一采用 3.5 mm，上下偏差等小字按适用规则采用较小字号。不要把允许小号偏差的规则用于整段中文技术要求。

SVG 的 `font-size` 是字体排版尺度，不必然等于字形墨迹的实际高度。核对所用字体的字面、字宽及打印效果，保证最终纸面可读。

空间不足时优先加宽单元格、换行或重新布局；不要让自动缩字号函数把中文静默降到允许字高以下。标题栏空白字段可以保留，不编造署名、审核记录或单位。

## 8. 尺寸、公差与表面要求的标注方法

### 8.1 一个尺寸必须有完整的测量语义

每个尺寸核对五件事：测量起止要素、尺寸界线、尺寸线、终端符号、尺寸文字。仅有一个数字及附近一根线，不代表标注成立。

根据工艺、装配和检验基准组织尺寸。靠近某个肩、孔或定位面的关键净距，优先从关联功能面直接控制，减少不必要的尺寸链累计。

区分模型尺寸链的几何闭合与图纸尺寸链的独立控制：模型应自洽，但总长及全部分段不应同时成为互相重复的独立约束；按适用规则选取参考尺寸或调整控制方式。

### 8.2 纸面尺寸标注的布局

- 尺寸界线从真实被测要素或其允许的延长处引出，不从任意轴线或空白点起算。
- 尺寸界线应按适用规则越过尺寸线。实现时先求“远离被测要素”的方向，再计算延长量，避免上下侧符号写反。
- 尺寸线、箭头及文字按所采用的一种标准标注方法统一布置。采用对齐式时，水平数字在线上方，竖向数字的阅读方向和位置保持一致。
- 直径、半径、槽宽、余厚和深度应有各自正确的标识、终点及引注方式。允许的直径引注不应被误禁，但漂浮文字也不能冒充直径标注。
- 狭窄处使用标准允许的外置箭头、引出文字或延长段，不强塞文字。文字移到外部后仍必须看得出属于哪一个尺寸。
- 尺寸线避免与轮廓、中心线重合；必要交叉按标准处理。文字及公差数字不被轮廓线、中心线、引线或箭头穿过。
- 尺寸尽量集中在表达对应结构最清楚的视图，不在多个视图重复给同一个独立控制尺寸。

### 8.3 公差不能从一个对象直接搬到另一个对象

尺寸公差、配合、几何公差和表面结构要求分别管理。键与键槽、轴与孔、槽深与余厚不是同一个受控对象。

当固定名义直径下将槽深 `t` 改为余厚 `q = d − t` 时，深度偏差的符号需反转；但若直径也有独立偏差，则实际余厚范围应由完整极限关系推导：

```text
q_min = d_min − t_max
q_max = d_max − t_min
```

若适用标准已经规定了工作图余厚的专用偏差注法，应按标准及其测量含义采用，不再随意叠加或重复约束。槽深与余厚也不应在没有必要时同时独立给定。

上下偏差应叠排、位置明确，不用斜杠写成含糊的文字串。排版时以“主值＋上下偏差”的整个组合计算宽高，不能只给主值让位。

一般尺寸公差不自动代替几何公差；已单独给定的公差也不能被总注覆盖。圆角、倒角的未注公差类别应单独核对，不能误套普通线性长度分档。

### 8.4 基准和几何公差要表达正确的对象

- 区分表面组成要素与由其导出的轴线、中心平面。基准符号连接位置必须表达设计所指要素。
- 表达圆柱面的导出轴线基准时，可按适用规则与其直径尺寸线对齐；不能用一根随意指向外圆的引线冒充轴线基准。
- 共同基准与主次基准体系不同，应采用各自规定的框格写法，不互相替代。
- 圆柱度等形状公差不引用基准；跳动等公差按其定义引用适当基准。公差值前是否加直径符号，取决于公差带形状，不能一律添加。
- 径向跳动指向被控制的回转表面，端面跳动指向端面。引线落点错误会改变技术含义。
- 公差符号优先使用经核对的矢量形状，避免字体缺字、近似 Unicode 图标或普通箭头替代正式符号。

公差数值由当前功能和设计依据给定；“标准规定如何标注”不等于“标准替当前零件选定所有数值”。

### 8.5 表面结构要求不能只写一个 Ra 数字

使用适用标准规定的表面结构符号，区分基本符号、要求去除材料和不允许去除材料的含义。符号方向、接触点、附加横线及参数文字应完整、清晰。

检查符号或引线实际指向哪个表面。槽侧面、槽底、密封带和定位端面不能含糊地共用一根落在空白处的引线。

局部要求优先于适用的其余表面总注；同一表面原则上不重复标注，且不得同时出现相互矛盾的要求。

## 9. 工作库的正确用法

本节对应当前工作区的 `mechanical-kit-main`。迁移到其他环境时重新确认路径及接口，不照搬操作系统绝对路径。

| 路径 | 用途 |
|---|---|
| `lib/drawing/_prim.py` | 图元 AST、图形容器及图元契约检查 |
| `lib/drawing/sheet.py` | 幅面尺寸、图框及标题栏辅助 |
| `draw/gbdraw.py` | 图元输出为 SVG、图纸坐标转换 |
| `skills/mechanical-homework/references/` | 制图流程与历史实现经验，使用前核对适用范围 |

当前已核对的基础接口：

```python
from lib.drawing._prim import (
    图形, 线, 圆, 弧, 矩形, 文, 剖面线, 箭头, 校验图元
)
from lib.drawing.sheet import 幅面尺寸, 图框, 标题栏
from draw.gbdraw import Sheet

# 以下是接口示意，变量由当前图样模型和布局提供，不是完整出图程序。
# 图元坐标是图纸毫米；默认 y 向上。
g = 图形()
g.加(线(x1, y1, x2, y2, style="thick"))
g.加(弧(cx, cy, radius, start_deg, end_deg, style="thick"))
g.加(文(tx, ty, label, h=text_height, anchor="middle"))

ok, message = 校验图元(g.elems, strict=False)
if not ok:
    raise ValueError(message)

sheet = Sheet(sheet_width, sheet_height, title=drawing_name)
sheet.add(*g.elems)
svg = sheet.svg()
# 再统一处理字体、稳定 ID、语义元数据，并写出 SVG。
# 上面的图元契约检查不负责判定投影、尺寸或画法是否正确。
```

基础参数顺序应特别留意：

```text
线(x1, y1, x2, y2, style)
圆(cx, cy, r, style, fill)
弧(cx, cy, r, a1, a2, style)
文(x, y, s, h, anchor, rotate, style)
箭头(x1, y1, x2, y2, size)    箭头尖在第二点
剖面线(poly, spacing, angle, style)
```

`校验图元` 默认 `strict=True`，失败时会抛出异常；示例使用 `strict=False` 后显式检查返回值。两种错误处理方式择一统一使用。

当前 `剖面线` 的 `poly` 是单个简单多边形的二维点序列，由函数自动闭合；它不直接接受圆弧路径或带孔的多环区域。曲边需要受控近似，带孔区域需要可靠分解或显式区间裁切，完成后仍核对真实实体边界，不能认为调用一次就已经正确扣除了所有孔槽。

建议在项目组装层封装可靠的 `尺寸、引线、公差框、表面符号、合并单元格`，底层仍使用工作库图元。确需补正库行为时，在项目层集中实现并注明原因；不要在 SVG 文本里反复替换孤立坐标。

### 已知实现风险及处理

| 风险 | 正确处理 |
|---|---|
| 高层尺寸函数的界线起点或延伸方向不适合当前结构 | 分别从两个真实被测要素构造界线，再核对实际输出 |
| 默认字体不是工程图要求的字体 | 明确替换字体样式并验证字体实际加载 |
| 标题栏或其他函数带有示例名称、材料等默认值 | 显式传入当前已确认字段，未知字段留空，不让库默认值变成设计输入 |
| 标题栏按完整网格画线，穿过应合并的名称或图号格 | 先定义合并单元格边界，只输出存在的格线 |
| 自动缩字使中文小于允许字高 | 设置字高下限，超宽时调整格宽或布局 |
| 默认基准、粗糙度或公差符号布局有误 | 按标准用基础图元重组，核对落点和框格 |
| AST 接受某图元，但当前 SVG 输出器未实现 | 同时核对 `_emit` 支持范围，先做小样渲染 |
| CSS 的 `fill:none` 覆盖元素 `fill` 属性 | 检查计算后的样式及渲染，不能只查属性文本 |
| 分组在输出时被展开，丢失分组级元数据 | 递归保存叶图元角色和特征 ID，再与实际 DOM 对应 |

当前路径翻转实现主要处理大写 `M/L/A` 及其支持的数值写法，不是通用 SVG 路径解释器。不要直接输入含相对命令、贝塞尔命令或未支持数值格式的任意路径。圆弧函数的扫掠方向还与坐标约定相关；切换 `y_up` 时先用已知象限的小样验证，不能假定全部原语都会自动适配。

圆弧、`pattern`、`clipPath` 并非在所有浏览器中天然失效。历史上某条链路的问题必须按当前版本复测。为方便离线核查与跨渲染器迁移，可优先把剖面线生成明确的裁切线段；不要把渲染器缺陷写成制图标准。

## 10. 字体必须真实落地

只写 `font-family: FangSong` 或其他字体名称不能证明目标机器实际使用了该字体；回退可能不报错，却改变字宽并造成穿线。

推荐流程：

1. 查明可用且允许分发的字体文件，记录来源、字体名和授权条件。
2. 单文件 SVG 优先使用经过验证的嵌入字体；使用外部字体时，将字体随图交付并验证引用路径。
3. 内联 SVG、直接打开 SVG、作为 `<img>` 引用 SVG，可能有不同的外部资源加载限制；必须检查实际交付的打开方式。
4. 渲染前等待 `document.fonts.ready`，核对字体资源加载状态和所需字符覆盖。单独调用 `document.fonts.check()` 仍不足以排除字体回退。
5. 检查中文、直径符号、正负号、上下偏差、长连接号及其他机械符号是否缺字或替换。
6. 子集化字体后，核对字符映射、字形及 advance width。保留子集不等于保留了正确字宽；不要未经验证手工重写字体表。
7. 最后对实际渲染文字取包围盒，不能一直依赖“中文一个字宽等于一个字号”的估算。

## 11. 排版先预留区域，再放引线

推荐布局顺序：

1. 固定图框和标题栏的合法区域。
2. 预留技术要求、必要表格及局部详图区。
3. 放置主视图及其他必要视图，暂不布置密集标注。
4. 分配尺寸带：先安排局部尺寸，外层安排总体尺寸，按实际读图关系调整。
5. 安排直径、圆角、几何公差和基准的独立空白区。
6. 从真实目标点布置引线，检查它是否穿过剖切字母、基准框及邻近文字。
7. 最后放表面符号、总注及其他辅助标记，重新计算全部包络。

视图的占用区域应包含中心线伸出段、剖切标注、尺寸界线、箭头、公差框和文字，不能仅按实体外廓排版。

建立标题栏等区域的“禁入区”，其他视图及其中心线、界线不得侵入。视图之间保留明确净距，避免虽未相交却被读成同一根连线。

同一条界线可以在规则允许且含义清晰时共用。仅在共线、线型相同、语义兼容且连续段适合合并时做区间并集；不对所有同坐标线条进行无条件合并。

## 12. 为每个图元保留可检查的身份

建议在生成时给图元保存下列元数据，并在 SVG 中输出稳定的 `id` 与 `data-*` 属性：

```text
feature_id     属于哪个实体或受控特征
view_id        属于哪个视图
role           outline / centerline / hidden / hatch / dimension /
               extension / leader / arrow / datum / tolerance-frame /
               roughness / text / title-grid / sheet
source         参数字段或画法依据
```

检查器依靠角色筛选目标，不用“所有斜线都是剖面线”“所有细长线都是尺寸线”这类猜测。尺寸线可结合其语义记录和两端箭头识别，避免把表格横线或引线尾端误判为尺寸线。

不要靠数图元判断结构完整。某张图的元素数量完全正确，仍可能漏一条孔口线并多一条错误弦线。

## 13. 自检必须包含四个层次

> **这一节已有可执行部分**：`lib/drawing/charter/check.py` 把第二层（几何）、第三层（字体与
> 图元碰撞）、以及线型/图层/尺寸标注/图框的常用判据实现为 46 条规则，一次给出「通过 /
> 不通过 / 未检查」三类，未检查项会逐条列出；`check_charter.py` 校验每条规则引用的条款
> 是否真实存在且状态为 A；`mutants.py` 往图里注错 24 处，验证检查器自己看得见。仍须人做的
> 判断（视图是否足够、投影方向、剖切表达、尺寸是否齐全）目前没有自动判据。

### 第一层：画法与技术语义审查

对照标准或同类原图逐项判断：视图是否足够、观察方向是否一致、可见边是否应存在、断面及其标准例外是否按规定表达、符号是否控制了正确对象、尺寸是否足够加工检验。

这一层可以由另一名 AI 独立审阅，但审阅者必须有模型及标准依据，不能只看一张整页缩图。意见存在分歧时回到投影和原图，不按代理人数投票。

### 第二层：模型与生成物的几何检查

至少检查：

- 各段连续性、总尺寸、孔槽位置及特征归属。
- 主视、端视、剖视、断面的对应位置、直径、槽宽、深度及方向。
- 各视图的真实比例及标注比例是否一致。
- 圆弧半径、端点、切线、倒角截短及轮廓拓扑。
- 极限公差下的圆角成形、孔槽净距及功能面保留。
- 必需边界、箭头、尺寸界线和剖切符号是否确实存在于最终 SVG。
- 剖面线是否落在被剖实体内部，是否侵入孔、槽、空腔或未剖区域。

输入模型与输出图必须分别核对来源。只比较两个由同一段错误代码生成的结果，不能发现上游输入错误。

### 第三层：实际字体及图元碰撞检查

渲染后检查下列类别，并逐类记录覆盖范围：

| 检查类别 | 必须注意 |
|---|---|
| 文字—文字 | 主值与偏差作为完整组检查；接近但不相交也要关注可读净距 |
| 文字—图形 | 包括直线、框边、箭头、圆、圆弧、路径及剖面线 |
| 标注—标注 | 引线穿框、重叠界线、跨越剖切字母及互相混淆 |
| 视图—视图 | 包含标注在内的区域冲突，防止中心线或界线连入另一视图 |
| 图元—图框 | 内容越界及侵入标题栏；纸边、图框本身按角色排除 |
| 重复线 | 完全重复、局部共线叠合及不同线型争用同一位置 |

相交并不都错误。轮廓连接、箭头接触目标、剖面线止于边界、中心线交于轴心及允许共用的图框边均可能合法。例外应按角色、特征关系、交点位置和范围识别，不能为了清零而删除合法图线。

#### 用浏览器实际坐标检查文字

`getBBox()` 给出的包围盒通常不包含该元素及祖先的全部变换，也不自动解决描边、滤镜和裁切问题。只读取它的 x、y、宽、高，会漏掉旋转或分组变换。

下面是将文本包围盒映射到根 SVG 用户坐标的通用片段；它不依赖具体零件参数。在已经插入 SVG 的页面中以模块脚本执行，或放入支持顶层 `await` 的浏览器控制台：

```javascript
await document.fonts.ready;
await new Promise(resolve => requestAnimationFrame(resolve));
const svg = document.querySelector('svg');
if (!svg || !svg.getScreenCTM()) throw new Error('SVG 尚未完成布局');

function boundsInRoot(el) {
  const b = el.getBBox();
  const rootMatrix = svg.getScreenCTM();
  const elementMatrix = el.getScreenCTM();
  if (!rootMatrix || !elementMatrix) throw new Error('元素没有有效变换矩阵');
  if (!rootMatrix.is2D || !elementMatrix.is2D) throw new Error('本片段只处理二维变换');
  const m = rootMatrix.inverse().multiply(elementMatrix);
  if (![m.a, m.b, m.c, m.d, m.e, m.f].every(Number.isFinite)) {
    throw new Error('根矩阵不可逆或变换结果无效');
  }
  const points = [
    [b.x, b.y], [b.x + b.width, b.y],
    [b.x + b.width, b.y + b.height], [b.x, b.y + b.height]
  ].map(([x, y]) => new DOMPoint(x, y).matrixTransform(m));
  return {
    id: el.id,
    xmin: Math.min(...points.map(p => p.x)),
    ymin: Math.min(...points.map(p => p.y)),
    xmax: Math.max(...points.map(p => p.x)),
    ymax: Math.max(...points.map(p => p.y))
  };
}

const textBounds = [...svg.querySelectorAll('text')].map(boundsInRoot);
```

本片段采集的是显式 `text` 元素，前提是图样已按本流程输出为明确、可见的图元。若导入图包含 `defs/use` 实例、隐藏元素、裁剪或遮罩，先处理实例与可见性；不能将该片段当作任意 SVG 的完整可见文字提取器。

对旋转文字，变换后的四边形更精确；上述轴对齐外包矩形用于保守筛查。误报处应检查真实字形区域，不靠随意降低阈值消警。

线条碰撞应计入至少半个描边宽度及纸面可读净距。圆和路径可做解析相交，或以受控弦高误差离散后检查；路径近似误差也应计入判定余量。

对实心箭头、基准三角形或其他填充区域，还应做区域相交及包含检查。仅检查多边形边线，会漏掉文字完全落在填充内部而未触及边界的情况。

若检查器只处理 `line/rect/poly`，必须明确写“未自动覆盖圆及圆弧路径”。剖面线即便逐条参与了文字碰撞检查，也不等于已经检查其对曲边实体的包含关系。

### 第四层：最终渲染与局部目视检查

同时检查整页及放大局部：主视、关键台阶、断面、密集公差区、表面符号、技术要求和标题栏。整页看布局与裁切，局部看文字、线型及连接。

视觉审阅不承担精确读数。数值与线位以模型、SVG 文本、坐标及校准后的像素探针核对；不要在缩图中反复猜小字。

## 14. 渲染流程必须可复现

建议按以下顺序执行，每一步失败即停止依赖它的下一步：

```text
读取并核对输入
→ 生成几何与标注 AST
→ 校验图元及几何关系
→ 导出 SVG，嵌入字体并附加语义 ID
→ 解析最终 SVG，核对尺寸文字及实际属性
→ 渲染当前 SVG，提取浏览器文字与图元数据
→ 检查碰撞、越界、重复线及视图关系
→ 全幅及关键局部目视复核
→ 修订后重跑受影响检查
→ 保存证据与版本标识
```

### 14.1 毫米与像素的映射必须量出来

SVG 根节点显式写物理尺寸及对应的 `viewBox`：

```xml
<svg width="Wmm" height="Hmm" viewBox="0 0 W H">
  <!-- W、H 在正式输出中替换为选定图幅的数值 -->
</svg>
```

PNG 核查时记录实际图面在图像中的原点、裁切范围及横纵比例：

```text
kx = 图面有效像素宽 / 纸面宽
ky = 图面有效像素高 / 纸面高
px = ox + kx × x_svg
py = oy + ky × y_svg
```

如从 y 向上的图纸坐标采样，先转换 `y_svg = H − y_sheet`。检查 `kx` 与 `ky` 是否一致，排除非等比缩放。不要假定所有浏览器截图或系统缩略图都没有留白，也不要固定采用某一次截图的像素比例。

以上简单映射以本流程的零原点 `viewBox` 和“一用户单位对应一纸面毫米”为前提。迁移其他 SVG 时，还需处理 `viewBox` 的 `minX/minY`、有效视口、宽高比留白及额外变换，不能直接套用。

像素探针避开中心线、交点、箭头和无关文字，并考虑线宽与抗锯齿。采样阈值和容差根据实际分辨率设定。稀疏白点只能证明那些点留白，不能证明整个槽区没有误填线。

### 14.2 确保核查的是同一个版本

每次生成记录输入文件摘要、生成脚本摘要、字体文件摘要、依赖版本、SVG 与预览图 SHA-256、时间及渲染器版本。最终自检记录引用这些标识。

渲染任务应记录它实际读取的 SVG 哈希、打开路径、所用参数和产出的预览哈希，形成输入到输出的关联。单独列出两个文件哈希只标识文件，不能自行证明该预览确实来自该版 SVG。

只看修改时间可能仍拿到缓存或旧预览；更稳妥的方法是绑定文件哈希。修改字体、线型或文字位置后，之前的碰撞结论也随之失效。

浏览器本地渲染优先采用正常安全设置；若环境存在特定 GPU 或沙箱问题，单独记录环境处理办法，不把某次机器所需的启动参数当作通用命令。字体、浏览器与运行时路径均应可配置。

### 14.3 只在需要时转换 PDF

SVG 是本流程的主交付格式；用户需要 PDF 时再增加转换步骤。打印时明确纸张、方向和零边距，关闭自动适应纸张，并核对 PDF 页数及实际页面尺寸，防止浏览器回退到默认纸张。

正确的 SVG 毫米尺寸，并不能自动证明打印后的 PDF 或纸质输出仍是正确比例。

## 15. 检查器自身也需要验证

关键检查不能只在正确图上返回“通过”。维护检查器时，可在临时副本中有针对性地注入错误，验证它能够报出对应问题，例如：

- 将一个断面的槽口旋转，确认视图对应检查失败。
- 移动一段文字穿过引线，确认文字碰撞检查失败。
- 删除一个尺寸箭头或必要孔口边，确认完整性检查失败。
- 在槽口保留完整圆弧，确认拓扑检查失败。
- 把一个槽宽文字改成与模型不同的值，确认输出文字核对失败。
- 改变极限偏差，使圆角不能成形，确认极限几何检查失败。

不要对每次小幅移字重复运行无关的大量测试；只运行适合本次变更的检查，再完成当前版本的交付门禁。上述注错用于证明检查器有识别能力，不代替标准画法审查。

## 16. 常见错误、修正方式与复查点

| 表现 | 根因 | 修正与复查 |
|---|---|---|
| 主视与断面尺寸不同 | 多份参数分别硬编码 | 改为同一特征模型驱动，比较还原后的真实量 |
| 槽口方向不对应 | 未定义视图坐标和观察轴 | 从特征方向向量重新投影，核对剖切箭头 |
| 槽口被完整圆穿过 | 先画整圆后忘记扣除缺口 | 直接生成开口轮廓，检查槽口角区及拓扑 |
| 圆弧多出一条弦线 | 使用自动闭合多边形 | 改用开放圆弧或开放折线，核对端点连接 |
| 名义轮廓可画，公差极限不能成形 | 只检查公称尺寸 | 核查最大圆角和最小台阶、实际净距 |
| 倒角看起来有，但尖角仍在 | 旧端面和旧母线未截短 | 删除不再存在的边段，按真实切点重建 |
| 引线穿字、穿基准框 | 只检查实体外形，没有检查标注包络 | 为文字和框保留区域，移动整组标注并重检 |
| 偏差数字压尺寸线 | 只给主值计算留白 | 将主值与上下偏差合组计算尺寸 |
| 标题栏横线穿过名称 | 合并格仍输出完整网格 | 按实际单元格边界重建格线 |
| 字体突然变宽或换形 | 静默字体回退或子集字宽损坏 | 核查字体加载、字符映射及实际文字包围盒 |
| 辅助功能带变成实体台阶 | 精度要求混入几何模型 | 将功能区移到精度层，用适用范围表示 |
| 自检零报错，实际仍有圆弧穿字 | 检查器未处理路径 | 补足路径覆盖，未补足前记录为未自动检查 |
| 所有线位同时误报 | 坐标重复翻转或截图偏移错误 | 标定根坐标到像素映射后再判断图是否需要修改 |
| 改完后预览仍像旧图 | 渲染失败、缓存或交付版本混用 | 检查执行结果与哈希，重建当前版本预览 |

同类问题反复出现时，先重新审查几何和视图方案。若错误来自视图类型或标准表达，继续挪动几毫米坐标不能解决根因。

## 17. 交付前的最终门禁

> `python3 lib/drawing/charter/check.py 图.svg --calc 计算书.json --fig-no CS2-01 --part shaft`，

> 尺寸线却穿过键槽长圆的例子。

- [ ] 输入结构、技术要求和图纸版本已确认，没有夹带其他零件的数据。
